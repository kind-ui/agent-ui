- Spec (binding): [`docs/superpowers/specs/2026-11-14-agent-ui-design.md`](docs/superpowers/specs/2026-11-14-agent-ui-design.md)

## Build on UI SDK

Every component is built on [UI SDK](https://ui-sdk.dev/docs), not around it. From spec §2 "Building on UI SDK":

> - Every public component and every internal general component is a `definePrimitive` definition, or a ready-made UI SDK component. Every React and Web Components render file renders through `createParts` (React and Web Components) or wraps a ready-made UI SDK component.
> - Focus management, keyboard navigation, popups, dismissal, selection, scroll following, live announcements, and ARIA roles and states come from UI SDK: slot `role`/`focus`/`press`/`keys` declarations, UI SDK components, and `@ui-sdk/core` behaviors (for example `createRovingFocus`, `createStickToBottom`, `announce`). Hand-written versions of these are not allowed.
> - Code written outside UI SDK is limited to the exceptions below. Each exception sits in a primitive's `api`, a slot's `on` handler, or a framework-free module in `core`, never in a render layer.
> - A new exception requires a spec change that adds a row to this table.

**Before writing or changing a component, read:**

1. The `ui-sdk` skill: `.agents/skills/ui-sdk/SKILL.md` (installed with `npx skills add`; the same skill ships at `node_modules/@ui-sdk/core/skills/ui-sdk/SKILL.md`). Follow it.
2. `node_modules/@ui-sdk/<framework>/docs/llms.txt`, where `<framework>` is `react` or `web`. It is the index; read it first.
3. To build a new component, search `node_modules/@ui-sdk/<framework>/docs/core.md` by heading for the behaviors you need, and read `docs/rendering.md` next to it.
4. The docs page of every UI SDK component you compose, for example `docs/components/collapsible.md`.

The installed docs describe the exact pinned version. Where the spec or plan names a UI SDK API whose signature differs, follow the installed docs and record the difference under "UI SDK API notes" below.

**Enforcement:** `npm run lint` runs `scripts/check-ui-sdk-usage.mjs`, which fails when:

- a `src/core/<component>/<component>.ts` (other than `motion/` and `markdown/`) does not export exactly one `definePrimitive` result as `<camelCase>Primitive`;
- a `src/react/**/*.tsx` or `src/web/**/*.ts` render file neither calls `createParts` nor wraps a `@ui-sdk/react/<name>` / `@ui-sdk/web/<name>` component;
- a render file hand-writes focus, keyboard, scroll, or ARIA code (`addEventListener`, `onKeyDown`, `tabIndex`, `.focus(`, `scrollTo`, `role=`, …);
- a core file does so without an entry in `scripts/ui-sdk-exceptions.json`, whose values must be exact "Exception" cells from the spec §2 table.

**Versions:** `@ui-sdk/core`, `@ui-sdk/react`, and `@ui-sdk/web` are pinned to one exact version. Upgrading any of them is a separate PR with its own changeset and a full `npm run check`.

## Verification policy

- **Quick checks while you work:** `npm run lint` and `npm run typecheck`, plus the unit tests or the one browser spec your change reaches. Run `npm run check` (browser suites included) once before you push.
- **Testing never slows implementation.** Build first, then test. Hand slow test work (full browser runs, flaky-test hunts, screenshot sets) to a subagent with only the command and the files it covers.
- **Before every push:** run `unslop` and `expert-review` on the diff.
- **Browser verification:** a PR reports what was checked in a real browser: keyboard, focus, reduced motion (`prefers-reduced-motion` and the `motion` option), and light and dark. Component PRs include light and dark screenshots, taken with nothing focused unless they show focus. Axe passing does not establish animation quality; check motion by eye and say what was not checked.

### Streaming UX acceptance checklist

Every component that shows streamed content passes these before its PR is ready:

- [ ] **Live edge:** it follows the newest content while the reader is at the end, and releases control the moment the reader scrolls away.
- [ ] **Mount-only pop-in:** a new row animates in once, when it mounts; updates to an existing row never replay the entrance.
- [ ] **No layout shift:** streaming text, status changes and late metadata do not move content above or beside them.
- [ ] **Compact completion:** tool and diff results collapse to a compact summary when they complete.
- [ ] **Approvals keep their outcome:** a resolved approval shows what was decided, not the buttons it had.

## UI SDK API notes

Differences between the plan's named APIs and the pinned UI SDK version. Tasks 2 and later fill this in.

- Pinned version: `0.1.0-beta.1`.
- `definePrimitive` is imported from `@ui-sdk/core`; `createParts` from `@ui-sdk/react/primitive` (React) and `@ui-sdk/web` (Web Components). Ready-made components import from `@ui-sdk/react/<name>` and `@ui-sdk/web/<name>`.
- **Web `createParts` (verified in Task 2):** `createParts(primitive, { root: string | RootOptions, <slot>: string | PartOptions }): Parts`. It registers each tag once and returns the element classes (`Root`, then each slot in PascalCase). A plain string maps a slot to a custom element that *is* the part. The plan's `{ root: "form", … }` tag map does not translate directly, because web tags must be custom element names. To keep native elements, map each slot to `{ tag, target, display: "contents" }`. `target` binds the slot's behavior and attributes to a native child: `wrappedChild("form")`, `wrappedChild("textarea")`, or `wrappedButton`. The custom element is a layout-free wrapper in light DOM, and Tailwind classes go on the native child. Parts find their root by walking up the DOM.
- **Option kind `"action"`:** in React the option is a function whose return value the primitive receives. On web it is a DOM event named after the option without `on` (`onSubmit` fires `submit` on the root element), and listeners call `event.detail.waitUntil(promise)`. Either way, the primitive gets a thenable to track pending state.
- **Declaration emit (TS2742):** an exported `definePrimitive(...)` result has an inferred type that references `SlotProps`, which no public `@ui-sdk/core` entry exports. Annotate it explicitly as `ReturnType<typeof definePrimitive<Options, State, Api, Record<SlotNames, SlotDefinition<State, Api, BaseSlotProps, Record<never, never>>>>>`. `BaseSlotProps` comes from `@ui-sdk/core/renderer`. `src/core/composer/composer.ts` shows the pattern.
- **`exactOptionalPropertyTypes`:** the type `definePrimitive` returns (`options: … | undefined`) is not assignable to UI SDK's own `Primitive` (`options?: …`) when this flag is on. `tsconfig.checks.json`, which covers the render layers, fixtures, and browser specs, turns the flag off. Core keeps it on.
- **Neutral types (Task 3):** `src/types/` models host data only (messages, parts, steps, tool calls, approvals). No UI SDK type describes this data, so nothing is reused from `@ui-sdk/*` there, and the `types` layer imports no runtime module. Component state and actions reuse UI SDK types in `core`.
- **Web root state and api:** a web root follows `@ui-sdk/web`'s own roots: `state` maps each controlled value to a live property through the primitive's getter and setter (`isOpen`/`setOpen`, `getValue`/`setValue`), and `api` lists the methods `element.api` exposes.
- **Agent bridge:** `createAgent` comes from `@ui-sdk/react/agent` or `@ui-sdk/web/agent`. A `definePrimitive` primitive's snapshot entry has `component` set to the primitive `name`, `label` set to the root's accessible name, the state keys listed in `controlled`, and `pending`.
- **AI SDK adapter (Task 4):** `adapters/ai-sdk` is not a UI SDK component, so the guard does not scan it. It imports `ai` with `import type` only. Differences between `ai@7.0.173` and spec §4.3 are recorded in `packages/agent-ui/README.md` under "Tested AI SDK version". `fromUIMessages` applies the chat status to the last message (any role), because with `submitted` the last message is the user's.
- **Motion helper (Task 5):** `motion@14.14.0` is exact-pinned. UI SDK `animateIn` / `animateOut` are CSS-driven: they only set `data-starting-style` / `data-ending-style` / `inert` and wait on `el.getAnimations()`, so `src/core/motion/` animates values with motion's `animate` and calls them for presence. `animateOut` finishes synchronously when no animation is running, so the helper always passes explicit `[from, to]` keyframes (current computed values when continuing, numeric strings parsed to numbers); motion then starts its WAAPI animation synchronously and `animateOut` waits for it. `@ui-sdk/core` does not export its `prefersReducedMotion`, so the helper reads `matchMedia` itself. An `enter` during `exit` rejects the exit promise with an `AbortError` (the element stays). Presets animate `transform` (which motion keeps on the compositor) and `layout` drives the separate `translate` and `scale` properties from a motion value, because motion replaces a running animation of the same property: a layout run is tracked apart and never stops an enter or exit. An interrupted run is cancelled with its values held inline, since motion's `stop()` commits them a frame later over the next run, and a finished run resolves in motion's render step so cleanup lands after motion's final write. `expand` animates from and to the `height` that `box-sizing` needs. `"dot-flow"` loops over `[data-dot]` children; reduced motion and `layout` under reduced motion apply the final state at once. `motion/index.ts` has a `ui-sdk-exceptions.json` entry ("Motion helper presets") for its `prefers-reduced-motion` change listener (`onReducedMotionChange`).
- **Internal components (Task 6):** React wrappers in `src/react/internal/` are the `@ui-sdk/react/<name>` parts passed through `withKindClass` (`kind-class.ts`), which puts Kind classes before the caller's `className` (string or state function) and passes every other prop through. Parts that render no element (`Menu`, `TokenInput`, `TriggerMenu`) are reexported as is. A wrapper whose `render` is another Kind wrapper renders that target's bare UI SDK part, so the element gets the outer wrapper's base classes once. The plan's `kind-internal-<name>` web tags cannot re-tag UI SDK elements: `@ui-sdk/web` parts find their owner with a fixed `ui-<name>` tag selector, and the core primitives alone lack the web glue (`list.js`, `popup.js`), so `createParts` cannot rebuild them. Instead, each `src/web/internal/<name>.ts` imports `@ui-sdk/web/<name>` (the entry registers the `ui-*` elements on import; there is no `define…Elements` export) and `defineInternal<Name>()` registers a `display: contents` host `kind-internal-<name>` whose Tailwind classes style the `ui-*` parts inside it through `[&_[data-slot=<slot>]]:` variants. Markup is `<kind-internal-menu><ui-menu>…</ui-menu></kind-internal-menu>`. The guard accepts a bare `import "@ui-sdk/web/<name>"` as wrapping a component. Internal wrappers do not animate; primitives that compose them use the motion helper.
- **Token Input whitespace:** the editor needs `whitespace-pre-wrap`, which token hosts inherit, so whitespace in a web `<template>` breaks the token onto its own line. The editor sets `whitespace-nowrap` on `[data-slot=token-input-host]`.
- **Markdown engine (Task 7):** `src/core/markdown/` is glue over pinned OSS, not a hand-written parser. `split.ts` splits blocks with `marked@18.2.0` `Lexer#blockTokens`, `space` tokens folded into the block before, a block final once it ends in `\n\n` with two blocks after it, and only the text after the final blocks lexed again. The HTML-tag and `$$` merging are left out (raw HTML renders as text, no math). Documents with link definitions stay one block, so `mdast-util-definitions` can resolve references; the lexer's `tokens.links` decides, so definition syntax inside code doesn't count. Footnotes split like other blocks: a `Tokenizer` override keeps marked from taking `[^x]: word` as a link definition, and a footnote's indented continuation joins its block. A reference renders as its own text whether or not its definition shares the parse, unless `(url)` follows it, which then renders as a link. `remend@1.4.0` repairs only the streaming last block (`katex: false`, `linkMode: "text-only"`); it does not close code fences, and none is needed because micromark runs an open fence to the end. URLs go through `micromark-util-sanitize-uri`'s `sanitizeUri(url, /^(https?|mailto)$/i)`: a URL with a leading space fails closed instead of being trimmed. Parsing uses `fromMarkdown` with `micromark-extension-gfm` + `mdast-util-gfm`; parse results are cached by block text with trailing newlines removed, so a block that just ended is not parsed again. Only `createMarkdownEngine`, `MarkdownBlock`, `MarkdownEngine`, and `MdNode` are public; `splitBlocks`, `repairTail`, `sanitizeUrl`, and `toMdNode` from the plan are internal or replaced by the libraries. A 20-character chunk can finish more than one block, so the acceptance test bounds parses by the blocks that were not final, not by 2. No highlighter ships (spec §6), so shiki is not added.
- **Step (Task 8):** `stepPrimitive` owns its trigger (`role: "button"`, `press`) and content slots and binds the content with `bindPanel` (`isFindable: true`, `hiddenAttrs(open || exiting, true)`), the same behaviors UI SDK Collapsible is built from. The render layers do not wrap the internal Collapsible: Collapsible would own `open` and the trigger element, and the skill forbids binding a second primitive's slot to an element one of UI SDK's already binds. `bindPanel` covers find in page, so `bindFindable` is not called separately. Panel motion is CSS on `bindPanel`'s `data-starting-style` / `data-ending-style` and `--kind-step-content-height`, keyed on `data-motion` and `prefers-reduced-motion` (height only at full motion; reduced is a 120 ms fade; `none` has no transition). The JS motion helper is not used here, because its `animateIn` / `animateOut` would drive presence a second time. `announce` takes `{ priority: "polite" }`, not a positional priority. Change details have no `"pointer"` or `"auto"` source: auto opens and closes report `reason: "auto"` with `source: "programmatic"`, and other changes carry UI SDK's sources (`mouse`, `keyboard`, `agent`, …). The agent bridge adds its generic `press` action to any component holding a button, so a step lists `expand`, `collapse`, and `press`.
- **StepList roving focus:** `focus: "roving"` on a slot does not write `tabindex`; the item's `attrs` returns `tabindex: part.api.roving.tabIndex(state, part)` as in UI SDK's rating guide, and the guard accepts a core `tabindex` only in that form. A trigger joins its list through `render` composition, as UI SDK's `ToolbarButton render={<MenuTrigger />}` does: React `<StepListItem value={id} render={<StepTrigger />}>`; web `<kind-step-list-item value="…"><kind-step-trigger><button>`. On web the list item targets the nested `button`, and the button keeps the trigger's `data-slot`. `createFocusRecovery` runs after the removed item has left `roving.items()`, so the list keeps the previous item order to pick the next sibling.
- **Motion tokens:** durations and easings live in `src/core/motion/tokens.ts`, which the motion helper imports. CSS reads the same values from `--kind-duration-*` / `--kind-ease*` in `agent-ui.css`, because a stylesheet cannot import TypeScript and the package has no CSS build step; `tests/core/motion.test.mjs` fails when the two differ. Loop timings (spin, pulse, shimmer, dot flow) are not tokens.
- **Step status glyphs:** the check, ✕ and minus are SVG paths used as CSS `mask` images on the icon's `::after`, so both render layers show the same centered glyph without extra markup. The running spinner is a full faint track plus an arc on `::before`. `data-motion` is on the trigger, icon and title too, so `motion="reduced" | "none"` stops the chevron, spinner and shimmer.
- **Shared styles:** Step styles live in `src/styles/step.css` (each component has its own file, like `conversation.css` or `markdown.css`) (imported by `agent-ui.css`), keyed on `data-slot` / `data-status` and `--kind-*` tokens inside `@layer components`, so both render layers render identically and a React `className` still wins. Fixture stylesheets import `agent-ui.css`.
- **Conversation (Task 9):** `conversationPrimitive` owns its `viewport` slot and binds `createStickToBottom` (and `createVirtualizer` with `virtualize`) to it; the render layers don't wrap the internal Scroll Area, whose viewport UI SDK already binds and whose `stickToEnd` would be a second follower on the same scroller (same reasoning as Step and Collapsible). The viewport declares `focus: "tab-stop"` with `tabindex: "0"`, as UI SDK's docs do for a focusable frame, so the keyboard can scroll a log with nothing focusable in it; the guard accepts one `tabindex: "0"` per `focus: "tab-stop"` in a core file. `nextFollowState` takes `{ type: "following" }` events, fed from `createStickToBottom`'s `following`, rather than the plan's `atBottom`: `following` is what the stick releases and resumes, while `atBottom` only says where the view is. Extra public pieces the plan left out: a `row` slot (`value`, `index`) that plays the mount-only entrance once per new index with the motion helper and is measured when virtualized (render virtualized rows keyed by index, with `rowKey` giving the virtualizer stable message keys, as UI SDK's "Rows of Any Height" does); an `onRowsChange` callback (web: `rowschange`, `detail.value`) and the content part's `rows` state; a `controller` option from `createConversationController()` (UI SDK `createController`) with `scrollToEnd`, `prepend`, `isFollowing` and `getRows`, which the web root lists as its `api`; and a `motion` option. `prepend()` calls the stick's `prepend` and makes the next count increase a `{ type: "prepend" }` event, so older history is never counted as new. `controlled: ["following", "newCount"]` puts both in the agent snapshot; neither is a host-controlled option. The jump control's text (`"Jump to latest"` / `"N new messages"`) is written by its `bind`, so both layers render it from one place; its `aria-label` starts with "Jump to latest", `announce` reads the count, and `aria-live="off"` keeps the log from reading the button again. Edge fades are a CSS scroll timeline (`@supports (animation-timeline: scroll())`) over `mask-image`, so they need no script and don't fade an edge with nothing past it; the end fade is off while `data-following` (the view trails new lines by a frame), and the root draws the viewport's focus ring, which the mask would hide.
- **Message, Markdown, Code Block and Markdown Table (Task 10):**
  - **Where:** the Markdown view is `src/core/markdown-view/` (`markdownViewPrimitive`, named `kind-markdown`), because `markdown/` is the engine and the guard names a primitive after its folder. Its state holds the engine (`engine` option, read at mount, else its own), so `state` parses for server render and the api appends to the same engine. Copying is `src/core/clipboard.ts` (`createCopy`: the spec §2 clipboard exception, `copied` for 2 s, `announce`); `@ui-sdk/core` has no clipboard utility. Slot keys with a dash (`"branch-label"`) give kebab `data-slot`s; camelCase keys stay camelCase.
  - **Actions offered while available:** the bridge lists an action only while `typeof api[name] === "function"`, read at each snapshot, so `regenerate`, `edit` and `setBranch` are api getters that return `undefined` when unavailable (`regenerate` and `edit` also until the message settles, as their buttons are). `branchCount` is in `controlled`, so the snapshot shows how many branches `setBranch` takes. UI SDK's development build warns once at mount that `agent.actions` names a method the api lacks; it's harmless. A web root's `api` list copies methods once, so it lists only `copy`.
  - **Web callbacks:** see "Web callbacks and availability" (Task 13): `can-regenerate` and `can-edit` offer those actions, which fire `regenerate` and `edit`; `onCopy` is a `messagecopy` event, since `copy` is a native event that bubbles. The option is `messageRole`, not `role`, which is the element's ARIA role (and the web attribute of the same name).
  - **Composing UI SDK:** Message's actions follow the skill's "wrap ours" seam: `MessageCopy` / `MessageRegenerate` / `MessageEdit` are `display: contents` slots around a `KindToolbarButton`, hearing its click bubble, so the internal Toolbar keeps its single Tab stop and arrow keys. Branch controls are the primitive's own `role: "button"` slots. No overflow Menu is composed: none of Wave 1's actions needs one; a host can add a `KindMenu` to the toolbar. Code Block's copy and wrap, and the table's copy, are the primitive's own button slots (as Step owns its trigger): a UI SDK Button or Toggle would bind the same element, and a Toggle would own `pressed`. Both compose the internal Scroll Area, with `ScrollAreaContent`, which `stickToEnd` watches for growth (a `display: contents` child gives it nothing to measure); Code Block's `streaming` turns `stickToEnd` on.
  - **Rendering blocks:** React keys blocks by index and memoizes each by its block object, because `block.key` changes with the streaming tail's text and would remount it every chunk; `data-block-key` still carries the key. Web renders in the root's `createParts` `render` hook (`OwnerConfig.render`, "data elements render their parts here"), patching only blocks whose object changed and reusing their nodes. `kind-code-block` and `kind-markdown-table` fill in their own parts when written empty (or with just a `<table>`).
  - **Highlight:** one request at a time, with `highlight` read when it starts (so an inline function is fine); a result applies while its code is still the start of `code`, with the rest plain, so streamed code doesn't flash back to plain text. A rejected request isn't retried until `code` or `language` changes. The option is `language`, not `lang`, the global attribute for an element's human language.
  - **Tables** use `table-layout: fixed`, so columns don't reflow as rows stream in; `--kind-markdown-table-columns` (set by Markdown) gives each column a minimum width, past which the table scrolls sideways.
  - **Internal wrappers:** the internal Toolbar is now borderless, and the Toolbar, Avatar and Scroll Area (ring and thumb) take their colors from `--kind-*` tokens; a toolbar button reads `--kind-toolbar-button-fg` for its color, so dark mode reads; Tailwind utilities can't be overridden from `@layer components`.
- **Composer and Attachments (Task 11):**
  - **Composing Token Input, Trigger Menu and File Input:** the composer follows the skill's "wrap ours" seam. Its api creates a `createTokenInputController()` (from `@ui-sdk/core/token-input`), which both layers pass as the Token Input's `controller`; the input part reads every edit through the controller's `editor.subscribe` (typing, tokens, removals, undo and `setValue` all report `input`) and writes the draft back with `setValue` when it differs. The draft's `text` is the Token Input's codec text (`[@label](kind:value)`), so a controlled draft round-trips through `fromText`. Enter (or Ctrl/Meta+Enter with `submitOn: "mod-enter"`, the Token Input's `submitShortcut`) submits the form the editor is in, and the root hears the form's `submit`: IME composition and an open Trigger Menu are the Token Input's to handle, so no `keys`/`on.keydown` submit policy was needed. The composer uses the bare UI SDK Token Input and File Input parts, styled from `composer.css`, because the internal wrappers' standalone field styling (border, minimum height) is the composer's box; it uses the internal Trigger Menu, whose colors now come from `--kind-*` tokens.
  - **Part state for render functions:** the root, input, trigger-menu and attachments slots hand the UI SDK component's props (File Input options, Token Input `controller`/`submitShortcut`, Trigger Menu `triggers`, Attachments `items`/`onRemove`) to render functions through slot `state`. A slot's state must keep its identity while its inputs do, or React renders the part again forever, so `api.partState` memoizes each. Web reads the same `api.partState` in the root's `createParts` `render` hook and writes the properties onto the `ui-*` elements, only when they changed; it redraws when elements arrive, so content added after the composer connects is wired too. The input syncs only once a Token Input has attached the controller (`connectInput`), since the controller reads `undefined` before that. A change the owner cancels writes the draft back to the editor. History recalls report `"history-key"`.
  - **File Input on web:** `@ui-sdk/web` reports File Input's changes only as non-bubbling `valuechange`/`reject` events on `ui-file-input`, so `core/file-input-events.ts` hears them as they capture through the form (spec §2 exception "Composer and Uploader File Input events on Web Components"); React gets the same handlers as props. The composer cancels each accepted change, so File Input holds no files: the draft does, rejected ones included with `error: "type" | "size"`.
  - **Agent confirm:** UI SDK's bridge reads `data-agent-confirm` per component, not per action, so the mark sits on the form and every composer action needs a person (or the host's `allow`) while `agentConfirm` is on.
  - **Focus:** Send and Stop take one place (`present`): Stop grows in through `@starting-style`, Send fades back in through the motion helper only when it returns from Stop. Then `createFocusRecovery` moves focus to whichever shows, else the editor; their `mousedown` is cancelled so a pointer press keeps focus in the editor. React consumers cancel a key in `onKeyDownCapture`: the Token Input handles keys on its element before React's bubbling `onKeyDown` runs.
  - **Attachments** mirror UI SDK's File Input list: a `list` of focusable `listitem`s with `createRovingFocus`, Delete/Backspace removing the focused item (spec §2 exception), and a pointer-only remove part hidden from assistive technology, like Token Input's. Image previews are object URLs made when an item binds (so the server and hydration render the icon) and revoked when it leaves. The composer's attachments part stays mounted while empty (`data-empty`), so the first chip plays its entrance.
- **Uploader and indicators (Task 12):**
  - **Uploader** composes the bare UI SDK File Input and Progress parts, styled from `uploader.css`, as the composer does, because the internal wrappers' neutral colors don't follow the `--kind-*` tokens. The host owns `items`; the uploader cancels each File Input change, so File Input holds no files. Rejected files go to an `onReject` option (web: `uploadreject` event), which the plan left out, mirroring File Input's own `onReject`; accepted ones go to `onFiles` (web: `files`). On web it hears File Input's events through `core/file-input-events.ts`, shared with the composer, so that spec §2 row now names both. Each row is the Progress (its label is the file name, so `aria-valuenow` and the name come from UI SDK), a detail line outside it (a `progressbar`'s children are presentational) and one `action` button that is Cancel while queued or uploading and Retry once failed: Retry turning into Cancel keeps the element and focus, and `createFocusRecovery` moves focus to a neighbor's button when a cancelled row's leaves (from the order before the change, since the row may be gone). A cancel or retry takes no second request for that item until the host changes its status, so a double press can't retry and then cancel. Rows present in the first frame after the root binds don't play the entrance, because a web host can only set `items` once the element exists; web moves rows with `moveBefore` where the browser has it, so a focused button stays focused. `progress` is 0 to 100, Progress's default range. Announcements are "<name> uploaded" and "<name> failed", on the transition only.
  - **Indicators** share one definition (`core/indicator.ts`) spread into each file's own `definePrimitive`, so the guard still sees one primitive per folder. The root is `role: "status"` named by `label` (also its visible text); the `dots` slot is `aria-hidden` and runs the `"dot-flow"` preset, a microtask after it binds, because web parts bind as they connect, before the dots inside have their `data-dot`. A `motion` change, or the person turning reduced motion on or off while `motion` is `"auto"` (the helper's `onReducedMotionChange`), restarts only the loop with the helper's `flow`, not the entrance; unbinding calls its `cancel(el)`. Loops end with motion's `cancel()`, since `stop()` writes the dots' opacity back a frame later. `DOT_FLOW.stagger` is 0.15 s, the plan's `i * 0.15`. Dots rest at 0.3 opacity under the loop and 0.6 when held still.
  - **Streaming Text** keeps `chunks` in state; `text` reaches it through `streamingTextDiff` in `api.onOptions` (not `sync`, which can't see the text before). Chunks before the first one still fading fold into one, so state and parts stay a handful however long the text. Appended chunks fade in with the `"fade"` preset only at full motion (`resolvedMotion`, newly exported by the helper), since spec §7 says reduced motion appends at once; a reset replaces every chunk with one that doesn't animate. It has no role and no live region: it is content, and its container announces. The caret is an empty inline with a positioned bar just after the text, so it adds no width or line height.
- **Web callbacks and availability (Task 13):** every web callback is a DOM event, as `@ui-sdk/web` makes them: `on<Name>` fires `<name>`, renamed through `events` where a bubbling native event inside takes the name (`messagecopy`, `composersubmit`, and the uploader's `uploadcancel`, `uploadretry` and `uploadreject`, beside its native file input's bubbling `cancel` and File Input's `reject`). React 19 sets a custom element's properties and listens to `on<event>` props, but can't set an `on…` function property, so none is public. Where a callback's presence offers an action (spec §6), a listener can't be seen, so a web-only boolean attribute does: `can-regenerate`, `can-edit`, `can-stop`, `can-remove`, `can-cancel`, `can-retry`, declared with root `kinds` and read by the root's `options` hook, which sets the callback to `undefined` while the attribute is off (`@ui-sdk/web`'s event proxy only fills in a callback whose key is missing). Non-`on` function properties are kept for values a callback must return (`highlight`). The composer hands its remove function to its `kind-attachments` as `removeHandler`, which offers removal without `can-remove`, and leaves it out while disabled. `tests/fixtures/react/cases/uploader.tsx` (`web-element`) renders `kind-uploader` from React 19.
- **Agent conformance (Task 13):** `tests/browser/wave-1/agent.spec.ts` runs one page (`?c=agent&case=all`) with every Wave 1 component in one `createAgent` snapshot. Each action runs once through `act` and once through the person's input on a fresh page, and the component's attributes and text must match (inline styles and `tabindex` aside: a pointer moves focus, an agent doesn't). A case module may export `allow`, which the fixture passes to `createAgent`. Markdown and Streaming Text have no role, so ARIA forbids naming them; they appear by kind, and they offer no actions.
- **StrictMode:** the `wave-1-react-strict` Playwright project runs every spec against a second React fixture server (`vite --mode strict`, port 4312) that wraps each case in `<StrictMode>`. A spec that depends on a single instance (UI SDK React creates and discards one under StrictMode) must not count side effects by index.
- **Theme tokens (Task 14):** `agent-ui.css` holds only `@import`s of the component stylesheets, one `@theme default` block and `@source` (`scripts/tests/styles.test.mjs` keeps it so). `default` makes a consumer's own `@theme` value win, and Tailwind emits the tokens in `@layer theme`, so an unlayered `:root` value wins too. Colors are `--kind-color-{fg,muted,surface,hover,border,ring,shadow,accent,on-accent,success,warning,danger}`; `muted` is secondary text and `hover` the subtle fill. `@theme` can't sit in a media query, so each color is a `light-dark()` pair: dark follows `color-scheme`, which the page sets (`light dark` to follow the system, `dark` on a dark theme's root), and a highlighter's `light-dark()` token colors switch with it. Radii scale from `--kind-radius` (`/ 3`, `/ 2`, `* 2 / 3`, `* 1.5`), so `0` squares every corner; pills and focus-ring radii stay fixed. The `kind-*` keyframes sit inside `@theme`, and Tailwind emits a token or keyframe only when a stylesheet uses it. `@source` registers `../react` and `../web` for apps that render the layers from the package source; the published `dist` has neither, and registry consumers' copied files are found by Tailwind's own detection. Internal wrappers' Tailwind classes read the tokens as `bg-[var(--kind-color-…)]`.
- **`tests/types/no-ai`:** `ai` is hoisted at the root, and a `paths` entry pointing at a missing file falls back to `node_modules`. The project maps `ai` to an empty stub (`ai-absent.d.ts`) instead. Types from `ai` need `skipLibCheck` (on in `tsconfig.base.json`), because `ai`'s own declarations fail under `exactOptionalPropertyTypes`. `no-ai` itself turns `skipLibCheck` off: each adapter `import type … from "ai"` carries a JSDoc `/** @ts-ignore */`, which, unlike a `//` comment, survives into the emitted `.d.ts`, so without `ai` those types are `any` instead of an error.

## Layer import rules (spec §2)

| Layer | Path | May import | Must not import |
| --- | --- | --- | --- |
| `types` | `packages/agent-ui/src/types/` | nothing | any runtime module |
| `core` | `packages/agent-ui/src/core/` | `types`, `@ui-sdk/core`, `motion`, the markdown libraries (spec §6) | React, other UI frameworks, `ai`, Tailwind |
| `adapters/ai-sdk` | `packages/agent-ui/src/adapters/ai-sdk/` | `types`, `ai` types | `core`, React, `@ui-sdk/*` |
| `react` | `packages/agent-ui/src/react/` | `@kind-ui/agent-ui/core`, `@ui-sdk/react` | `ai`, `web` |
| `web` | `packages/agent-ui/src/web/` | `@kind-ui/agent-ui/core`, `@ui-sdk/web` | React, `ai` |

Render layers import core only through `@kind-ui/agent-ui/core`, never a relative path, so the registry can copy them byte-for-byte.

## Conventions

- TypeScript is strict with NodeNext modules, explicit `.js` import suffixes, and named reexports only (no `export *`).
- Primitive names are `kind-<component>`. Web Component tags are `kind-<component>` and `kind-<component>-<part>`, rendered into light DOM.
- Styling is Tailwind v4 utilities keyed on `data-*` attributes; data-driven values use `--kind-*` CSS variables.
- Tests use fixtures and explicitly resolved deferred promises only: no live services, timing sleeps, or model calls.
- `@kind-ui/agent-ui` stays `"private": true` at `0.0.0`. Nothing publishes without a maintainer's explicit authorization.
