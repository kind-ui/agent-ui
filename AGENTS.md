## Build on UI SDK

Every component is built on [UI SDK](https://ui-sdk.dev/docs), not around it. From spec §2 "Building on UI SDK":

> - Every public component and every internal general component is a `definePrimitive` definition, or a ready-made UI SDK component. Every React and Web Components render file renders through `createParts` (React and Web Components) or wraps a ready-made UI SDK component.
> - Focus management, keyboard navigation, popups, dismissal, selection, scroll following, live announcements, and ARIA roles and states come from UI SDK: slot `role`/`focus`/`press`/`keys` declarations, UI SDK components, and `@ui-sdk/core` behaviors (for example `createRovingFocus`, `createStickToBottom`, `announce`). Hand-written versions of these are not allowed.
> - Code written outside UI SDK is limited to the exceptions below. Each exception sits in a primitive's `api`, a slot's `on` handler, or a framework-free module in `core`, never in a render layer.
> - A new exception requires a spec change that adds a row to this table.

**Before writing or changing a component, read:**

1. The `ui-sdk` skill: `.agents/skills/ui-sdk/SKILL.md` (installed with `npx skills add`; the same skill ships at `node_modules/@ui-sdk/core/skills/ui-sdk/SKILL.md`). Follow it.
2. `node_modules/@ui-sdk/<framework>/docs/llms.txt`, where `<framework>` is `react` or `web`. It is the index; read it first.
3. To build a new component, search `node_modules/@ui-sdk/<framework>/docs/core.md` by heading for the behaviors you need, and read `docs/rendering.md` next to it.
4. The docs page of every UI SDK component you compose, for example `docs/components/collapsible.md`.

The installed docs describe the exact pinned version. Where the spec or plan names a UI SDK API whose signature differs, follow the installed docs and record the difference under "UI SDK API notes" below.

**Enforcement:** `npm run lint` runs `scripts/check-ui-sdk-usage.mjs`, which fails when:

- a `src/core/<component>/<component>.ts` (other than `motion/` and `markdown/`) does not export exactly one `definePrimitive` result as `<camelCase>Primitive`;
- a `src/react/**/*.tsx` or `src/web/**/*.ts` render file neither calls `createParts` nor wraps a `@ui-sdk/react/<name>` / `@ui-sdk/web/<name>` component;
- a render file hand-writes focus, keyboard, scroll, or ARIA code (`addEventListener`, `onKeyDown`, `tabIndex`, `.focus(`, `scrollTo`, `role=`, …);
- a core file does so without an entry in `scripts/ui-sdk-exceptions.json`, whose values must be exact "Exception" cells from the spec §2 table.

**Versions:** `@ui-sdk/core`, `@ui-sdk/react`, and `@ui-sdk/web` are pinned to one exact version. Upgrading any of them is a separate PR with its own changeset and a full `npm run check`.

## Verification policy

- **Quick checks while you work:** `npm run lint` and `npm run typecheck`, plus the unit tests or the one browser spec your change reaches. Run `npm run check` (browser suites included) once before you push.
- **Testing never slows implementation.** Build first, then test. Hand slow test work (full browser runs, flaky-test hunts, screenshot sets) to a subagent with only the command and the files it covers.
- **Before every push:** run `unslop` and `expert-review` on the diff.
- **Browser verification:** a PR reports what was checked in a real browser: keyboard, focus, reduced motion (`prefers-reduced-motion` and the `motion` option), and light and dark. Component PRs include light and dark screenshots, taken with nothing focused unless they show focus. Axe passing does not establish animation quality; check motion by eye and say what was not checked.

### Streaming UX acceptance checklist

Every component that shows streamed content passes these before its PR is ready:

- [ ] **Live edge:** it follows the newest content while the reader is at the end, and releases control the moment the reader scrolls away.
- [ ] **Mount-only pop-in:** a new row animates in once, when it mounts; updates to an existing row never replay the entrance.
- [ ] **No layout shift:** streaming text, status changes and late metadata do not move content above or beside them.
- [ ] **Compact completion:** tool and diff results collapse to a compact summary when they complete.
- [ ] **Approvals keep their outcome:** a resolved approval shows what was decided, not the buttons it had.

## UI SDK API notes

Differences between the plan's named APIs and the pinned UI SDK version. Tasks 2 and later fill this in.

- Pinned version: `0.1.0-beta.1`.
- `definePrimitive` is imported from `@ui-sdk/core`; `createParts` from `@ui-sdk/react/primitive` (React) and `@ui-sdk/web` (Web Components). Ready-made components import from `@ui-sdk/react/<name>` and `@ui-sdk/web/<name>`.
- **Web `createParts` (verified in Task 2):** `createParts(primitive, { root: string | RootOptions, <slot>: string | PartOptions }): Parts`. It registers each tag once and returns the element classes (`Root`, then each slot in PascalCase). A plain string maps a slot to a custom element that *is* the part. The plan's `{ root: "form", … }` tag map does not translate directly, because web tags must be custom element names. To keep native elements, map each slot to `{ tag, target, display: "contents" }`. `target` binds the slot's behavior and attributes to a native child: `wrappedChild("form")`, `wrappedChild("textarea")`, or `wrappedButton`. The custom element is a layout-free wrapper in light DOM, and Tailwind classes go on the native child. Parts find their root by walking up the DOM.
- **Option kind `"action"`:** in React the option is a function whose return value the primitive receives. On web it is a DOM event named after the option without `on` (`onSubmit` fires `submit` on the root element), and listeners call `event.detail.waitUntil(promise)`. Either way, the primitive gets a thenable to track pending state.
- **Declaration emit (TS2742):** an exported `definePrimitive(...)` result has an inferred type that references `SlotProps`, which no public `@ui-sdk/core` entry exports. Annotate it explicitly as `ReturnType<typeof definePrimitive<Options, State, Api, Record<SlotNames, SlotDefinition<State, Api, BaseSlotProps, Record<never, never>>>>>`. `BaseSlotProps` comes from `@ui-sdk/core/renderer`. `src/core/composer/composer.ts` shows the pattern.
- **`exactOptionalPropertyTypes`:** the type `definePrimitive` returns (`options: … | undefined`) is not assignable to UI SDK's own `Primitive` (`options?: …`) when this flag is on. `tsconfig.checks.json`, which covers the render layers, fixtures, and browser specs, turns the flag off. Core keeps it on.
- **Neutral types (Task 3):** `src/types/` models host data only (messages, parts, steps, tool calls, approvals). No UI SDK type describes this data, so nothing is reused from `@ui-sdk/*` there, and the `types` layer imports no runtime module. Component state and actions reuse UI SDK types in `core`.
- **Web root state and api:** a web root follows `@ui-sdk/web`'s own roots: `state` maps each controlled value to a live property through the primitive's getter and setter (`isOpen`/`setOpen`, `getValue`/`setValue`), and `api` lists the methods `element.api` exposes.
- **Agent bridge:** `createAgent` comes from `@ui-sdk/react/agent` or `@ui-sdk/web/agent`. A `definePrimitive` primitive's snapshot entry has `component` set to the primitive `name`, `label` set to the root's accessible name, the state keys listed in `controlled`, and `pending`.
- **AI SDK adapter (Task 4):** `adapters/ai-sdk` is not a UI SDK component, so the guard does not scan it. It imports `ai` with `import type` only. Differences between `ai@7.0.173` and spec §4.3 are recorded in `packages/agent-ui/README.md` under "Tested AI SDK version". `fromUIMessages` applies the chat status to the last message (any role), because with `submitted` the last message is the user's.
- **Motion helper (Task 5):** `motion@14.14.0` is exact-pinned. UI SDK `animateIn` / `animateOut` are CSS-driven: they only set `data-starting-style` / `data-ending-style` / `inert` and wait on `el.getAnimations()`, so `src/core/motion/` animates values with motion's `animate` and calls them for presence. `animateOut` finishes synchronously when no animation is running, so the helper always passes explicit `[from, to]` keyframes (current computed values when continuing, numeric strings parsed to numbers); motion then starts its WAAPI animation synchronously and `animateOut` waits for it. `@ui-sdk/core` does not export its `prefersReducedMotion`, so the helper reads `matchMedia` itself. An `enter` during `exit` rejects the exit promise with an `AbortError` (the element stays). Presets animate `transform` (which motion keeps on the compositor) and `layout` drives the separate `translate` and `scale` properties from a motion value, because motion replaces a running animation of the same property: a layout run is tracked apart and never stops an enter or exit. An interrupted run is cancelled with its values held inline, since motion's `stop()` commits them a frame later over the next run, and a finished run resolves in motion's render step so cleanup lands after motion's final write. `expand` animates from and to the `height` that `box-sizing` needs. `"dot-flow"` loops over `[data-dot]` children; reduced motion and `layout` under reduced motion apply the final state at once. `motion/index.ts` has a `ui-sdk-exceptions.json` entry ("Motion helper presets") for its `prefers-reduced-motion` change listener (`onReducedMotionChange`).
- **Internal components (Task 6):** React wrappers in `src/react/internal/` are the `@ui-sdk/react/<name>` parts passed through `withKindClass` (`kind-class.ts`), which puts Kind classes before the caller's `className` (string or state function) and passes every other prop through. Parts that render no element (`Menu`, `TokenInput`, `TriggerMenu`) are reexported as is. A wrapper whose `render` is another Kind wrapper renders that target's bare UI SDK part, so the element gets the outer wrapper's base classes once. The plan's `kind-internal-<name>` web tags cannot re-tag UI SDK elements: `@ui-sdk/web` parts find their owner with a fixed `ui-<name>` tag selector, and the core primitives alone lack the web glue (`list.js`, `popup.js`), so `createParts` cannot rebuild them. Instead, each `src/web/internal/<name>.ts` imports `@ui-sdk/web/<name>` (the entry registers the `ui-*` elements on import; there is no `define…Elements` export) and `defineInternal<Name>()` registers a `display: contents` host `kind-internal-<name>` whose Tailwind classes style the `ui-*` parts inside it through `[&_[data-slot=<slot>]]:` variants. Markup is `<kind-internal-menu><ui-menu>…</ui-menu></kind-internal-menu>`. The guard accepts a bare `import "@ui-sdk/web/<name>"` as wrapping a component. Internal wrappers do not animate; primitives that compose them use the motion helper.
- **Token Input whitespace:** the editor needs `whitespace-pre-wrap`, which token hosts inherit, so whitespace in a web `<template>` breaks the token onto its own line. The editor sets `whitespace-nowrap` on `[data-slot=token-input-host]`.
- **Markdown engine (Task 7):** `src/core/markdown/` is glue over pinned OSS, not a hand-written parser. `split.ts` splits blocks with `marked@18.2.0` `Lexer#blockTokens`, `space` tokens folded into the block before, a block final once it ends in `\n\n` with two blocks after it, and only the text after the final blocks lexed again. The HTML-tag and `$$` merging are left out (raw HTML renders as text, no math). Documents with link definitions stay one block, so `mdast-util-definitions` can resolve references; the lexer's `tokens.links` decides, so definition syntax inside code doesn't count. Footnotes split like other blocks: a `Tokenizer` override keeps marked from taking `[^x]: word` as a link definition, and a footnote's indented continuation joins its block. A reference renders as its own text whether or not its definition shares the parse, unless `(url)` follows it, which then renders as a link. `remend@1.4.0` repairs only the streaming last block (`katex: false`, `linkMode: "text-only"`); it does not close code fences, and none is needed because micromark runs an open fence to the end. URLs go through `micromark-util-sanitize-uri`'s `sanitizeUri(url, /^(https?|mailto)$/i)`: a URL with a leading space fails closed instead of being trimmed. Parsing uses `fromMarkdown` with `micromark-extension-gfm` + `mdast-util-gfm`; parse results are cached by block text with trailing newlines removed, so a block that just ended is not parsed again. Only `createMarkdownEngine`, `MarkdownBlock`, `MarkdownEngine`, and `MdNode` are public; `splitBlocks`, `repairTail`, `sanitizeUrl`, and `toMdNode` from the plan are internal or replaced by the libraries. A 20-character chunk can finish more than one block, so the acceptance test bounds parses by the blocks that were not final, not by 2. No highlighter ships (spec §6), so shiki is not added.
- **Step (Task 8):** `stepPrimitive` owns its trigger (`role: "button"`, `press`) and content slots and binds the content with `bindPanel` (`isFindable: true`, `hiddenAttrs(open || exiting, true)`), the same behaviors UI SDK Collapsible is built from. The render layers do not wrap the internal Collapsible: Collapsible would own `open` and the trigger element, and the skill forbids binding a second primitive's slot to an element one of UI SDK's already binds. `bindPanel` covers find in page, so `bindFindable` is not called separately. Panel motion is CSS on `bindPanel`'s `data-starting-style` / `data-ending-style` and `--kind-step-content-height`, keyed on `data-motion` and `prefers-reduced-motion` (height only at full motion; reduced is a 120 ms fade; `none` has no transition). The JS motion helper is not used here, because its `animateIn` / `animateOut` would drive presence a second time. `announce` takes `{ priority: "polite" }`, not a positional priority. Change details have no `"pointer"` or `"auto"` source: auto opens and closes report `reason: "auto"` with `source: "programmatic"`, and other changes carry UI SDK's sources (`mouse`, `keyboard`, `agent`, …). The agent bridge adds its generic `press` action to any component holding a button, so a step lists `expand`, `collapse`, and `press`.
- **StepList roving focus:** `focus: "roving"` on a slot does not write `tabindex`; the item's `attrs` returns `tabindex: part.api.roving.tabIndex(state, part)` as in UI SDK's rating guide, and the guard accepts a core `tabindex` only in that form. A trigger joins its list through `render` composition, as UI SDK's `ToolbarButton render={<MenuTrigger />}` does: React `<StepListItem value={id} render={<StepTrigger />}>`; web `<kind-step-list-item value="…"><kind-step-trigger><button>`. On web the list item targets the nested `button`, and the button keeps the trigger's `data-slot`. `createFocusRecovery` runs after the removed item has left `roving.items()`, so the list keeps the previous item order to pick the next sibling. Both live in `core/list-focus.ts` (`createListFocus`), which every list of focusable items shares.
- **Motion tokens:** durations and easings live in `src/core/motion/tokens.ts`, which the motion helper imports. CSS reads the same values from `--kind-duration-*` / `--kind-ease*` in `agent-ui.css`, because a stylesheet cannot import TypeScript and the package has no CSS build step; `tests/core/motion.test.mjs` fails when the two differ. Loop timings (spin, pulse, shimmer, dot flow) are not tokens.
- **Status mark:** `src/styles/status-mark.css` draws any element with `data-status-mark` from its `data-status` (every `StepStatus`, plus `skipped`, a minus like `cancelled`). The check, ✕ and minus are SVG paths used as CSS `mask` images on `::after`, so both render layers show the same centered glyph without extra markup. The running spinner is a full faint track plus an arc on `::before`. `data-motion` is on the trigger, icon and title too, so `motion="reduced"` (and `prefers-reduced-motion`) fades the fill and glyph over 120 ms with no scale or spin, and `"none"` transitions nothing.
- **Shared styles:** Step styles live in `src/styles/step.css` (each component has its own file, like `conversation.css` or `markdown.css`) (imported by `agent-ui.css`), keyed on `data-step-part` / `data-status` and `--kind-*` tokens inside `@layer components`, so both render layers and every Step-based component render identically and a React `className` still wins. Fixture stylesheets import `agent-ui.css`.
- **Web first render:** `@ui-sdk/web` gives each part its attributes as it connects, and some binds read style (`bindPanel` calls `getAnimations()` on a panel bound open; Scroll Area measures), so the parts after them, on the page too, get a style without their attributes and their transitions run once those land. `holdTransitions` (`core/step/base.ts`) sets `data-mounting` on the Step root and on each Task, Plan and Chain of Thought row until its second frame, and `step.css` turns off transitions under it.
- **Step base (Wave 2 Task 1):** `core/step/base.ts` holds everything of Step but its name: `stepBase({ kind, announcement })` (`announcement(status, title, state)` replaces the default text, or returns `undefined` to stay quiet) returns `options`, `state`, `sync`, `controlled`, `api`, `slots` and `agent`, which `stepPrimitive` and each Step-based component spread into their own `definePrimitive` (as the indicators spread `indicator.ts`), wrapping `state`, `api` and `slots` to add their own. Every base slot writes `data-step-part="<slot>"`, and StepList's root `data-step-part="list"`; `dropRow` drops a row only while it's still leaving, so an exit that ends after the host brought the item back drops nothing. `bindStepPanel` is the content slot's `bindPanel` call, for item panels a component owns; `stepAnnouncement` is the default text. The option that names a step in announcements is `label`, not `title`: on Web Components `title` is HTML's tooltip attribute, and `@ui-sdk/web`'s `AttributeProperties` leaves out every `HTMLElement` key. `core/leaving.ts` (`mergeLeaving`, `dropRow`, `LeavingRow`) keeps removed host items as leaving rows (spec §6 "Removed items").
- **Reasoning (Wave 2 Task 3):** `reasoningPrimitive` spreads `stepBase<ReasoningState>` and passes `definePrimitive` its type arguments, since inference takes `StepOptions` from the base `api`. It keeps five of the base slots (no `meta` or `children`), adding slot `state` by spreading the base definition into `slot({ ...title, state })`: `definePrimitive` calls `slots` with an identity `slot`, so a definition is a plain object. Its `title` (the `label`, else `reasoningTitle(status, durationSeconds)`) and `text` are in state through `sync`. The base hands `announcement` the store merged with the `synced` state `onOptions` receives, because the store takes `synced` only after the listeners run; on Web Components each attribute is its own options change, so `duration-seconds` set after `status` misses the announced summary (the docs say to set it first). The content renders the Markdown view, `streaming` while `running`: React through `ReasoningContent`'s default children, web by writing `source` and `streaming` onto the `kind-markdown` in its content from the root's `render` hook, as `kind-status` fills its label. It streams through the Markdown view the budgets already cover, so `budgets.spec.ts` has no Reasoning case: in React, `text` in step state also renders the root, trigger, icon, title and content once per chunk, a fixed cost that doesn't grow with the text. `reasoning.css` styles the thoughts and the finished mark through `--kind-markdown-{font-size,line-height,color}` and `--kind-status-mark-complete`, so a class on the content or icon part restyles them.
- **Tool (Wave 2 Task 4):** `toolPrimitive` spreads `stepBase<ToolState, ToolApi, ToolOptions>`; the base's new `status` config gives the status when the host passes none (`toolStatus(call)`), and the base reads it for auto open and announcements. Its state is flat strings and booleans (`input`, `outputText`, `inputCopied`, …) computed from `call`, so the store sees only the fields a call update changed. `createCopy(context, key)` writes its own state key, so the input and output copy buttons each keep their "Copied". The error part is present while the status is `error` (the plan said `outcome === "error"`), so a host `status="error"` shows its message too. Input and output render Code Block without its header (React `header={false}`, web `<kind-code-block headerless>`, read when it fills in its parts), so the Tool's copy buttons are the only ones; the code blocks inside still appear in the agent snapshot with their own `copy`. The "Partial" and "Preliminary" badges are always in the markup and shown by the part's `data-state`, so both layers share one rule. Web writes the title, approval and error into empty parts, fills an empty `kind-tool-input` or `kind-tool-output` with its heading, copy button and code block, and writes the values into them from the root's `render` hook, as Reasoning does. `copyInput` and `copyOutput` are api getters, `undefined` while there's nothing to copy, so neither is in the web root's `api` list. A denial announces "<name> denied" through the base's `announcement`, though its status is `cancelled` (spec §4.1). `budgets.spec.ts` streams one tool's input among 10 and 500: React renders one tool's parts (25; Code Block's scroll area is a shared element tree) and web re-reads one tool's parts (17), whatever the count.
- **Chain of Thought (Wave 2 Task 5):** `chainOfThoughtPrimitive` spreads `stepBase` for the summary and keeps its steps as data (`steps`), keyed by id, as UI SDK's Accordion keeps its items: `openSteps` (controlled, with `defaultOpenSteps`, which the plan left out, and `onOpenStepsChange`) and `exitingSteps` are id lists in state, `stepsById` is a record, and every item part's `selects` reads them by its own key, so opening or closing a step reaches only its parts (a host `steps` write still renders every step's parts in React, through UI SDK's options change). Parts inside an item take its `value` through `{ kind: "string", from: "item" }`, typed optional as Accordion's are, so `createListFocus` now takes any `Props extends object` (it reads only the key). `panels` is `live` state, as Accordion's is: a trigger's `aria-controls` names its content only while that content is in the page, since a host may render a step without one. Each step's auto open runs `nextOpenSteps` (spec §5's `nextOpen` per step whose status changed, a new step counting as from `pending`); the trigger, find in page and `expandStep` count as toggles, a host `openSteps` write doesn't. Each step's terminal transition is announced as `stepAnnouncement(status, title)`, joined with the others and the chain's own into one `announce` per update, because a polite `announce` replaces one still waiting (the chain passes the base a silent `announcement` and announces its status itself); steps set in the first frame aren't announced. `agent.items` lists the steps as `{ value: id, label: title }` with `closed: true`, because the bridge lists items only through `setValue` or `agent.items`, so an agent can pass `expandStep` a title and an unknown one is refused. Steps after the first frame play the `"fade-up"` entrance once, as Uploader rows do; a removed step leaves at once (D1, host-rendered children). The title defaults to the `label`, else "N steps", and the meta parts show `stepDuration` ("N s"). Item parts write the Step base's `data-step-part`s, so `step.css` styles them; `chain-of-thought.css` only joins the marks into a line. Web adds a `kind-chain-of-thought-item` for each step its list lacks and removes only those it added, and gives every item without a trigger the default one, so a host writes items only to give steps content; an item it writes after its step replaces the one the element added, and lookups stay inside the element's own chain. The web root's state has `openSteps` (`getOpenSteps` / `setOpenSteps`) beside `open`, so a moved element keeps its open steps.
- **Task and Plan (Wave 2 Task 6):** both spread `itemList` (`core/item-list.ts`), which wraps `stepBase` as the indicators share `indicator.ts`: `items` keyed by id in state (`itemsById`, read through `ownItem` `selects`), a `list` of focusable `listitem`s on `createListFocus` (`data-step-part="item"`, `aria-current="step"` on the running one), `meta` state `{ done, total }` from `itemProgress`, and the Chain of Thought announcement pattern (items' terminal transitions and the root's joined into one `announce`; items in the first frame neither announce nor play the `"fade-up"` entrance). The base `status` config defaults the root's status to `itemsStatus` (error, complete, running, pending), so a host can pass items alone. An item's mark is `role="img"` named by its status, since the item's status needs text. UI SDK Timeline has the same list shape, but spec §7 names `createRovingFocus` and Timeline's statuses are `complete`/`current`/`upcoming`. Plan composes the bare UI SDK Progress parts inside its `progress` slot, as Uploader does, and keeps it outside the content so it shows while closed; `accept` is outside too, so a closed plan still offers it. `onAccept` is an `"action"` option: `accept` sets `pending` and settles on the returned value through `Promise.resolve`, and a focus recovery moves focus to the trigger when Accept leaves while focused. Web declares `defaults: { agentConfirm: true }`, as the composer does: without it, setting `agentConfirm = false` left confirmation on. `item-list.css` styles the items of both; `plan.css` the progress bar and Accept.
- **Subagent (Wave 2 Task 7):** `subagentPrimitive` spreads `stepBase` and keeps every base slot, adding `avatar`, `cancel` and `result`; `onCancel` is an `"action"` option settled as Plan's `onAccept` is, and `cancel` is listed only while `onCancel` is set, the status is `pending`, `running` or `awaiting-input`, and none is pending. Stop sits after the content, as Plan's Accept does, so it never moves the header when it leaves, and `createFocusRecovery` moves its focus to the trigger. The avatar composes the bare UI SDK Avatar parts, styled from `subagent.css`, because the internal wrapper's 32px size is a Tailwind utility no component layer can override; it is `aria-hidden` with an empty `alt`, since the title beside it names the subagent (UI SDK Avatar's own accessibility advice). The plan's `result` part has no content to test for `data-empty`, so the host passes `result` (markdown, rendered by the Markdown view, as Reasoning's `text` is), and a part with nothing in it hides through `:empty` (web leaves it empty without a `result`). React `Subagent` puts its children, the nested steps, in its children part inside the content, unlike the other Step-based components whose children replace their parts: a subagent's steps are host elements, not data. `SubagentRoot` is the bare root for arranging the parts. Web can't move the host's nodes that way, since React 19 then loses track of them (`insertBefore`/`removeChild` throw on the next render), so a host writes the steps inside a `kind-subagent-content` and the element adds its trigger before that and Stop and the result after it, unless it has a trigger of its own; lookups skip nested subagents. `avatarInitials` takes each word's first grapheme (`Intl.Segmenter`), skips words that start with neither a letter nor a digit, and keeps a character whose upper case is longer ("ß"). A cancel is announced as "<name> stopped", matching Stop. The meta part reads the status in words (`subagentStatus`), so the status has text beside its mark.

## Layer import rules (spec §2)

| Layer | Path | May import | Must not import |
| --- | --- | --- | --- |
| `types` | `packages/agent-ui/src/types/` | nothing | any runtime module |
| `core` | `packages/agent-ui/src/core/` | `types`, `@ui-sdk/core`, `motion`, the markdown libraries (spec §6) | React, other UI frameworks, `ai`, Tailwind |
| `adapters/ai-sdk` | `packages/agent-ui/src/adapters/ai-sdk/` | `types`, `ai` types | `core`, React, `@ui-sdk/*` |
| `react` | `packages/agent-ui/src/react/` | `@kind-ui/agent-ui/core`, `@ui-sdk/react` | `ai`, `web` |
| `web` | `packages/agent-ui/src/web/` | `@kind-ui/agent-ui/core`, `@ui-sdk/web` | React, `ai` |

Render layers import core only through `@kind-ui/agent-ui/core`, never a relative path, so the registry can copy them byte-for-byte.

## Conventions

- TypeScript is strict with NodeNext modules, explicit `.js` import suffixes, and named reexports only (no `export *`).
- Primitive names are `kind-<component>`. Web Component tags are `kind-<component>` and `kind-<component>-<part>`, rendered into light DOM.
- Styling is Tailwind v4 utilities keyed on `data-*` attributes; data-driven values use `--kind-*` CSS variables.
- Tests use fixtures and explicitly resolved deferred promises only: no live services, timing sleeps, or model calls.
- Nothing publishes without a maintainer's explicit authorization: Publish waits for approval of the `npm-release` environment.

## Releasing

- `.github/workflows/release.yml` runs on a push to `main` that changes the version in `packages/agent-ui/package.json` (a merged version PR), or by hand through `workflow_dispatch` with `version` (the manifest's version) and `dist-tag` (default `latest`).
- npm tries OIDC trusted publishing first and falls back to `NODE_AUTH_TOKEN`, which the Publish step reads from the `NPM_TOKEN` secret in the `npm-release` environment. A trusted publisher can only be added once the package exists on npmjs.com, so the first publish uses the token.
- After the first publish, add the trusted publisher on npmjs.com (GitHub Actions, repository `kind-ui/agent-ui`, workflow `release.yml`, environment `npm-release`, allowing `npm publish`), then delete the `NPM_TOKEN` secret and revoke the token. A new trusted publisher expires unless it publishes within 2 days.
