# Web Components expert: decisions

What is already decided, and what is known and open. The expert never re-raises a **Settled** item as a finding.

Last reviewed: 9994de73

## Settled

- **The Vue, Svelte and Solid layers follow React's structure, not Web's (framework layers plan, 2026-11-20):** the Web layer's `draw` hooks, `can-*` attributes and renamed events are Web Components needs that the component frameworks don't share. `wave-1/light-dom.spec.ts` stays Web-only.
- **`kind-connection-status` fires `connectionretry`, not `retry`** (Wave 6 Task 7): it sits inside a `kind-conversation`, which fires its own `retry` for its error state, and a capture listener on the conversation hears both (UI SDK events don't bubble, but capture still passes ancestors). A distinct name, as `uploadretry` is, keeps them apart without checking `event.target`.
- **A Dictation in a shadow root nested inside the Composer doesn't reach it (Task 17):** `insertText` walks `parentElement`, as a button in a shadow root doesn't submit an outer form.
- **Effort Slider was scrapped by the user (Wave 5 Task 8, 2026-11-17):** effort is a radio submenu in Model Control, a Settings Menu (`settingsBase`). Don't propose a slider or nested popover for effort.
- **A `kind-model-selector` element icon is cloned with its ids** (Wave 4 Task 12b): rewriting ids inside each copy would be fragile; the `models` JSDoc says to pass a logo with `defs` as an image URL, and the fixture's Google monogram, with a gradient in `defs`, is one.
- **`drawIcon` compares icons by identity** (suspected, Wave 4 Task 12b): a host that builds new elements on every `models` write re-copies its icons, which is harmless.
- **A hand-written empty `kind-inline-citation-content` stays empty** (Wave 4 Task 3), as React's bare `InlineCitationContent` does: the element fills in only the content it wrote.
- **`kind-sources`' `api` leaves out `expand` and `collapse`** (Wave 4 Task 2): they are availability getters, and a web root's `api` list copies methods once, as Guardrail Notice's does; `open` and `setOpen` cover them.
- **Fixtures carry no comments** (Wave 3 Task 11): the agent page builds `kind-model-selector` and `kind-reasoning-effort` with `createElement` because `defaultValue` is a property read when the element connects (AGENTS.md, Wave 3 agent conformance), not because markup was overlooked.
- **`kind-suggestion` fills in only its own row** (Wave 3 Task 7): a row a page writes is the internal Carousel's markup with its `kind-suggestion-item`s, as a written `kind-reasoning-effort` holds its own Segmented Control; the element's JSDoc says so. There are no `kind-suggestion-viewport`/`-previous`/`-next` tags.
- **`kind-task` and `kind-plan` look up their parts with `querySelector`,** not Chain of Thought's `own()`: no part of theirs holds arbitrary content, so no nested task or plan sits inside one.
- **`notified` in `budgets.spec.ts` counts shown parts only** (hidden parts sync without `getAttribute`), at most the jump and empty parts, constant across list sizes. The `remount` fixture keeps the last unmounted tree until the next mount; leaks are measured while mounted.
- **Theme defaults land on `:root, :host`** (Tailwind's `@theme` output), so inside a shadow root that loads the stylesheet a page's `:root` override doesn't reach; the README tells consumers to set `:host` there too. It also makes the stylesheet work when loaded only in a shadow root.
- **`can-<action>` attributes stand for a callback's presence;** the root's `options` hook sets the callback to `undefined` while one is off. A listener can't be seen, and `@ui-sdk/web`'s proxy fills in a dispatcher for any callback key that's missing.
- Everything in AGENTS.md "UI SDK API notes".
- **WebKit presses Uploader's Cancel and Retry with Enter in `uploader.spec.ts`:** WebKit doesn't focus a button on click, so focus recovery can only be checked from the keyboard there; Chromium and Firefox cover the click.
- **Internal host classes stay per file.** A shared `defineHost` helper in `src/web/internal/` would be a render file that neither calls `createParts` nor wraps a component, which the guard rejects.
- **A status change while a `kind-status` is out of the document isn't announced when it returns:** nobody could see the change.
- **`kind-model-control`'s `model` and `effort` setters refuse while disabled, and `effort` while the model has no levels,** as Settings Menu's `values` refuses while disabled (Wave 5 Task 9).
- Sidebar with `side="end"`: the handle's `aria-valuenow` and `aria-controls` are the inset's, since UI SDK's splitter reports the panel before the handle. That's the window splitter pattern; kept.

## Known and open (don't report again, check whether fixed)

## Resolved

- **`nearestTabStop` searched only `ownerDocument.body`** (found in Wave 6 Task 7, fixed in Task 12): it now walks the flat tree (open shadow roots and slots), so a Notice or Connection Status hands focus where Tab would go, inside a shadow root or out of a slot.
- **An empty written `<kind-dictation-status>` showed nothing (Wave 5 Task 11):** `draw` fills in its mark and `[data-dictation-text]`.
- **Context Bar (Wave 5 Task 10):** a list written with only whitespace inside is filled in; new chip objects with the same content keep their rows; the content's `initial-focus`, `side-offset` and `align` are set on every draw, so content added later opens as React's does (`written` case).
- **A `kind-message` written with menu markup and no `regenerateOptions` both regenerated and opened a menu of "Try again" (Wave 5 Task 7):** the root now always controls its `ui-menu`, which refuses to open without options, and empties a content it owns; `message.spec.ts` has a `no-options` case.
- **`hearComposed` didn't tell nested components apart (Wave 5 Task 1, fixed in Task 7):** an element nearer the event's target that hears the same event name now takes it, so an outer root no longer hears a nested component's `ui-*` events; `composed-events.spec.ts` nests one `kind-test-menu` in another and fails without the fix.
- **`placeMenuChild` re-added every row on each redraw (Wave 5 Task 5):** a row already in place was moved before itself, which in WebKit (no `moveBefore`) dropped focus and closed a submenu; Task 4's Add Menu fix only held in Chromium. It now leaves the row, and Settings Menu draws a choice's options by value; `settings-menu.spec.ts` counts zero removals on a value change and an equal `settings` copy.
- **`kind-add-menu` rebuilt every row on an `items` change, dropping focus (Wave 5 Task 4):** rows are now drawn by `id` and moved only when out of place; a written empty `ui-menu-content` fills itself in. Spec covers both.
- **Model Selector's Combobox `anchor` through `data-model-selector-field`** (Wave 5 Task 3): Model Selector moved onto Picker, whose popup anchors to its own trigger; the field and its anchor are gone.
- **Wave 4 agent conformance** (Wave 4 Task 12): the web `case=wave-4` page draws the same text as React for all eleven Wave 4 components, and its `can-*` attributes add and remove their actions (`agent.spec.ts`).
- **Selection and Action** (Wave 4 Task 11): empty written `kind-action-quote`, `kind-action-result` and `kind-selection-item` parts are filled in as React's defaults are; a `kind-selection` in a shadow root opens (core reads `getComposedRanges`); web fixtures use the tag map's element types.
- **A web Transcript shorter than its viewport raised a ResizeObserver loop error** (Wave 4 Task 10): fixed; the viewport has a fixed `--kind-transcript-height`, so measuring segments never resizes it, and the spec fails on any window `error`.
- **`kind-test-results` missed a filter or tree written later, or written with whitespace inside** (Wave 4 Task 9): `draw` looks both up each time, a `MutationObserver` redraws when parts arrive, and whitespace-only parts count as empty. Pinned in `test-results.spec.ts` (late case).
- **`kind-stack-trace` (Wave 4 Task 8):** a moved element folded its shown library frames (root `state` now maps `showLibraryFrames`); written empty frames, groups, toggles and frame parts stayed empty (now filled from state, as React's defaults are; `written` fixture case); a new `label` or an equal `frames` copy rebuilt every frame node (the list now redraws only when its rows, entries or `canOpen` change by content).
- **Terminal (Wave 4 Task 7):** the follow test used a click WebKit doesn't focus with and read `scrollTop` mid smooth scroll in Firefox; it now presses Enter in WebKit and waits for the scroll to rest. A put-back element is tested to redraw its lines and keep `open`.

- **`kind-file-tree` put back after a tick lost its controller and state, and WebKit blurred a row** (Wave 4 Task 6): `render` sets the Tree's `controller` each draw, root `state` maps `value` and `expanded` (new `setValue`/`setExpanded`), and `drawRows` removes rows that left before placing the rest. Pinned in `file-tree.spec.ts` (moved case); `@ui-sdk/web/tree` joins `optimizeDeps`.
- **Generated Image's axe test crashed Firefox** (Wave 4 Task 5): a locator query right after axe and a DOM change crashes the page; the spec waits for the phase with `waitForFunction` first. Add this trigger to the upstream report beside the `ui-radio` one.
- **`kind-document` replaced its Downloads on any `downloads` change, added one beside a written Download, and wiped written content text** (Wave 4 Task 4): Downloads it added are kept by `value` and moved with `moveBefore`, a written `kind-document-download` replaces them all, and content is filled only with no element or text in it; the `written` case and a focus-through-change test pin them.
- **Reordering `kind-inline-citation`'s sources blurred a focused link** (Wave 4 Task 3): slides move with `moveBefore` where the browser has it.
- **Sources (Wave 4 Task 2):** the axe tests reach the trigger with a CSS locator (Firefox crash), and closing inside a shadow root returns focus to the trigger.
- **Step-based elements played color transitions on first render (Task, Plan, Chain of Thought, Tool).** Cause: `@ui-sdk/web` gives each part its attributes as it connects, and a part that reads style as it binds (UI SDK `bindPanel`'s `getAnimations()` on a content bound open, Scroll Area's measure in a code block) styles the parts after it, on the page too, bare. Fixed: the step root holds `data-mounting` until its second frame, and `step.css` turns transitions off under it; state changes still animate.
- **Notice and Guardrail Notice (Wave 3 Task 10):** Dismiss stays the last child when a host adds text or buttons after the element connects (moved with `moveBefore` where the browser has it), so Tab reaches them first; a notice removed and put back neither rises in nor is announced again.
- **Feedback (Wave 3 Task 9):** a `kind-feedback` removed and put back a tick later couldn't send the comment its textarea kept (the comment text slot binds `bindText`, tested); the docs say `rating` and `defaultRating` are properties only.

- **Checkpoint (Wave 3 Task 5):** setting `restored` with the dialog open left the page `inert` (a hidden web part keeps its dialog), and Firefox crashed running axe after a role query on the trigger (axe tests reach it with a CSS locator; add the Tooltip/Alert Dialog trigger to the upstream report).
- **`kind-question` rebuilt its choices for a new array with the same content, and written items didn't win (Wave 3 Task 4).** Fixed: options are compared by content, a written item replaces the added one wherever it sits, and one written empty is filled in (`question.spec.ts`, web).
- **Tool code-block names (Wave 2 Task 10):** `kind-tool` names only the code blocks it wrote, so a host's own code block keeps its `aria-label` (tested).

- **A focused chip or uploader row blurred when an earlier one was dropped (Wave 2 Task 9).** Fixed: `draw` removes dropped rows before placing the rest, so no row after them moves; the focus specs check again once the row is gone, and pass in Chromium, Firefox and WebKit.
- **Queue (Wave 2 Task 8):** `kind-queue` keeps its open sections when it leaves the page and comes back (`openSections` root state, restored through `defaultOpenSections`); sections written after it connects are filled in through a `MutationObserver`; `KindQueueElement` types its `api`.
- **Subagent (Wave 2 Task 7):** `kind-subagent` no longer moves the host's children (React 19 threw on `insertBefore`/`removeChild`): the host writes steps inside `kind-subagent-content` and the element adds its parts around it; without a `result` the result part stays empty and hides.

- **A hand-written `kind-tool` with empty input and output parts showed nothing (Wave 2 Task 4).** Fixed: the root fills an empty `kind-tool-input` or `kind-tool-output` with its heading, copy button and code block.
- **Leaving out a code block's header needed internal markup in a JS string (Wave 2 Task 4).** Fixed: `<kind-code-block headerless>`, read when it fills in its parts, like React's `header={false}`.
- **`kind-tool` rewrote `hidden` on its output blocks every update (Wave 2 Task 4).** Fixed: guarded like its other writes.
- **`kind-status` and `kind-reasoning` stopped updating their label or title after leaving the page and coming back a tick later (Wave 2 Task 3):** UI SDK rebuilds the instance, and each kept the parts it filled in per instance. Fixed: one module-level set; `status.spec.ts` and `reasoning.spec.ts` cover it.
- **`title` on `<kind-step>` was HTML's advisory attribute (Wave 2 D4).** Checked in Chromium: it stays on the element, so it's the tooltip over the whole step and the group's accessible description. Fixed: the option is `label` in both layers.
- **No `HTMLElementTagNameMap` entries, and no types for `can-*` or `removeHandler` (Wave 2 Task 1).** Fixed: each web file exports `Kind<Name>Element` (events with reasons read from core, live state, `api`, `can-*` properties, host-set properties) and declares every tag it defines, `kind-internal-*` included; the web fixtures listen without casts, so a wrong event name fails the typecheck.
- **WebKit `following a new message` read 16 layouts:** the opening scroll-to-end's late scroll event landed in the measured window; the test now waits two frames after opening (Task 18).
- **Docs captions (Task 17):** the Conversation and Composer pages now say `rowKey`, `controller` and `defaultValue` are properties only.

- **`kind-step` and `kind-composer` exposed no `api` or live state.** Fixed: `state: { open }` / `state: { value }` and `api` lists, as `@ui-sdk/web` roots do (`StepApi.isOpen`, `ComposerApi.getValue`).
