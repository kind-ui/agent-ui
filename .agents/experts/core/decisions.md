## Settled

- **`appendText` returns `true` for a controlled composer before the owner applies the value (Task 17):** it goes through `createChange`, as `setValue` does.
- **Dictation keeps its run when the host passes a new `source` object (Wave 5 Task 11):** only dropping `source` cancels, since React hosts often write the source inline, a new object each render; the new source is used from the next start.
- **Effort Slider was scrapped by the user (Wave 5 Task 8, 2026-11-17):** effort is a radio group in Model Control, a Settings Menu (`settingsBase`), listed in the menu itself after the models since Design Wave 1 Batch B (`inline` choice rows). Don't propose a slider, a submenu or a nested popover for effort.
- **Model Selector's `icon` is `unknown` in core, so each render layer casts once where core hands it over** (Wave 4 Task 12b): `definePrimitive` can't be generic per instance, and each layer types its own public `models` (`string | ReactElement` in React, `string | Element` on web), so no other value reaches the cast.
- **Selection's `onDismiss` hears Escape, an outside press and `dismiss`, not a selection collapsing** (Wave 4 Task 11): a collapse is the reader moving on, not a dismissal; the JSDoc says so.
- **Selection's root is a `group` named by `label`, which names its Toolbar too** (Wave 4 Task 11): the bridge names a component by its root, and a generic `div` can't carry a name; the same name twice is the cost of one "Selection actions" agent entry.
- **A Test Results suite whose id is `all`, `fail`, `pass` or `skip` shares an agent item value with a filter** (Wave 4 Task 9): the bridge checks one list per component, and `expand("fail")` still opens the suite; hosts use real ids.
- **Test Results' `failure` part cancels every click inside its Stack Trace** (Wave 4 Task 9, spec §2 row): UI SDK's Tree would otherwise toggle the row; the trace's buttons have already run. A link added inside Stack Trace later would need its default kept.
- **A double-click on a File Tree file calls `onSelect` twice** (Wave 4 Task 6): each press is an activation, as Suggestion's `onPick` is; a host that opens files dedupes.
- **Generated Image with `status` `"ready"` and no `src` shows "Loading image"** (Wave 4 Task 5): an error there would flash, and announce, whenever a web host sets `status` before `src`; the `src` JSDoc says to set it with or before `ready`.
- **The Step root writes `data-mounting` in its `bind`, not through `attrs`** (Wave 3 Task 11): it lasts two frames per element and isn't state, so a store flag would render every React part again to clear it; `wave-3/agent.spec.ts` checks no Step part runs a transition on load. **`imports` in `size-budget.json` is required:** the file is ours, and a missing key fails the check.
- **A dismissed notice the host never removes stays faded and inert** (Wave 3 Task 10, D10): the host removes it in `onDismiss`; only a rejection brings it back.
- **A Feedback comment that failed keeps its error and text until the next send** (Wave 3 Task 9), through a close and a rating change: the error belongs to the text it failed to send, which the box still holds.
- **Suggestion's `pick` has no lock** (Wave 3 Task 7): `onPick` is a `callback`, as the plan says, so a double press calls it twice. A host whose pick sends a prompt drops a repeat itself, as it would for a double-clicked send.
- **Checkpoint `defaultOpen` logs UI SDK's dev warning that `agent.actions` lists `restore`** (Wave 3 Task 5): `restore` is a getter that returns `undefined` while the dialog is open, as the other Wave 3 actions do.
- **Checkpoint's `restored` isn't in `controlled`** (Wave 3 Task 5): on web a boolean attribute turned off reads `undefined`, which made UI SDK warn that it stopped controlling it. An agent sees Restore gone and "Restored" instead.
- **A denial in a Tool is announced twice, "Denied" then "<name> denied" (Wave 3 Task 3):** spec §4.1 keeps the recorded response and the resulting execution state apart; Confirmation announces the first and Tool its outcome, and a host sets them in separate updates.
- **`kind-queue`'s web `api` lists no `reorder` or `remove`:** both are getters that return `undefined` while unavailable, and a web root's `api` list copies methods once (AGENTS.md, Task 10 "Actions offered while available"). Hosts call them through the agent bridge or the core api.
- **UI SDK's dev warning that `agent.actions` lists `cancel` (or `accept`) while the api lacks it** is expected: those actions are getters that return `undefined` while unavailable (spec §6), and the warning is once per mount (AGENTS.md).
- **A Tool's error part follows its status, not `outcome` (Wave 2 Task 4):** a host `status="error"` shows its message too, and a host status over an errored call hides it. The JSDoc and AGENTS.md say so.

## Resolved

- **Style guards missed `outline-color`, `font` shorthands, offsets and Tailwind ring classes** (Design Wave 0 review): `scripts/tests/styles.test.mjs` now checks all four.
- **`nearestTabStop` missed shadow roots (Wave 3 Task 10, fixed in Wave 6 Task 12):** it walks the flat tree, as Tab does: an open shadow root in its host's place, a slot's assigned elements where the slot is, and an inert ancestor of the lost element counts as passing it. It stops at the first stop after the lost element, so it reads less than the old whole-page filter. `connection-status.spec.ts` moves focus into a shadow root, to a slotted child, and out of a slot to the shadow button after it.
- **Message's relative time didn't roll over at midnight (Wave 6 Task 9, fixed in Task 12):** the time part now joins Day Separator's page-wide minute clock (`core/today.ts`, `everyMinute`), one timer for the page however many messages; a `now` option still replaces the clock. `message.spec.ts` runs the clock past midnight.
- **`checkServer` (`tests/core/ui-sdk-testing.test.mjs`):** destroying a Context Bar, Feedback, File Tree, Question, Reasoning Effort, Test Results or Transcript on a server threw (`cancelAnimationFrame` isn't defined there); each cancels a frame only when it asked for one. Dictation read `document` as it was created (`sourceOf()`); it starts input tracking as its root binds.
- **Question's radio group had no name** (`checkPattern("radio-group")`): `choicesState` carries the prompt as `label` for a single choice, which both layers set as the radio group's `aria-label`. A checkbox group stays unnamed, a group inside the question's own named group.
- **Dictation (Wave 5 Task 11):** a non-finite `bars` threw (now the default, capped at 64); dropping `source` while listening left the microphone open (cancels now); a throwing `onText` was an unhandled rejection (rethrown from a microtask); `joinFinals`/`dictationError` are module-private; `error` is in `controlled`. Unit tests pin the first two.
- **Context Bar (Wave 5 Task 10):** a focused chip pushed behind "+N" (a resize, a chip added in front) went `inert` and dropped focus to the page; `show` now hands focus to the last chip shown with `roving.focus` (the guard accepts `roving.focus(`), tested by narrowing the bar. The chip and row slots declare their `keys`. `createListFocus`'s recovery filter was dropped: `roving.items()` already returns only focusable items.
- **Message's regenerate menu stayed open after the toolbar left or an agent regenerated (Wave 5 Task 7):** `menuBase` gained `canOpen`; the menu closes when there are no options, no `onRegenerate` or an unsettled message, and after an agent's `regenerate`; pinned in `message.spec.ts`.

- **`menuBase`'s data cache was shared by every instance (Wave 5 Task 4):** two Add Menus updating in turn re-notified; `toData` now returns one array per input (Add Menu caches it per sections) and the cache checks identity first. Unit test with two instances.
- **Model Selector marked matches only in the name** (Wave 5 Task 3): on Picker it marks a description too, only when the name didn't match, as Picker does.
- **Model Selector's list anchored through the field's `id`** (Wave 4 Task 12b, core, react and web reviews): an author `id` on the trigger, a page element with the same id or a `"` in it broke the anchor; the trigger now writes `data-model-selector-field` and the anchor is an escaped selector for it, and the `logos` case has a trigger with an author `id`.
