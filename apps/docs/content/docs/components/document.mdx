Use a document when the agent hands over a file, like a README, a script or notes, rather than a reply. It shows the title with what the document is and its size, Copy and Download in a toolbar, and the content in a preview that expands to show it all.

```bash tab="React"
npx shadcn@latest add @kind-ui/document
```

```bash tab="Web Components"

```

## Composition

```text
Document
├── DocumentHeader
│   ├── DocumentTitle
│   ├── DocumentMeta
│   └── DocumentToolbar
│       ├── DocumentCopy
│       └── DocumentDownload
└── DocumentBody
    ├── DocumentContent
    └── DocumentExpand
```

`Document` is a region named by its title. `DocumentTitle` shows the `label`, and `DocumentMeta` what the document is (Markdown, Text, or the code's `language`) and its size, like "Markdown · 2.4 kB". `DocumentToolbar` is a toolbar with `DocumentCopy` and a `DocumentDownload` for each format. `DocumentBody` holds `DocumentContent` in a scroll area, and `DocumentExpand` is **Show more** while the content is taller than the preview. To arrange the parts yourself, pass them as children of `Document`.

## Usage

### Formats

Pass the source as `content` and say how it shows with `format`. `"markdown"`, the default, renders through [Markdown](./markdown.mdx), `"code"` through a [Code Block](./code-block.mdx) without its header, and `"text"` as plain text that wraps. Give code its `language`, which shows beside the title and goes to `highlight`, as Code Block's does.

```tsx
<Document label="backoff.ts" format="code" language="ts" content={source} />
```

### Copy and Download

**Copy** writes `content` to the clipboard, shows a check for two seconds and announces "Copied". Cancel `onCopy`'s details to copy something else yourself.

**Download** shows while `onDownload` is set. The component never builds or fetches a file: it calls `onDownload` with the chosen format's `id`, and your handler saves it, as the example's `save` does. With more than one of `downloads`, each format has its own button showing its `label` and named "Download" and that label, like "Download Markdown"; with one or none, there's a single **Download**. In a card under 28rem wide, the buttons show only their glyph, so the title keeps its room. Return a promise to keep Download pending until it settles; if it rejects, the component announces "Download failed".

The toolbar is one Tab stop. Use the arrow keys to move between its buttons, and Enter or Space to press one.

### Preview

The preview shows the document up to `--kind-document-max-height`, 20rem by default, and scrolls inside, with its edges fading while there's more past them. Once the content is taller, **Show more** sits over the preview's end; press it to show the whole document and **Show less** to collapse it. Pass `defaultOpen` to start expanded, or `open` with `onOpenChange` to control it.

At full motion the preview slides open; under `prefers-reduced-motion`, or with `motion="reduced"` or `"none"`, it changes height at once.

### Streaming

Set `streaming` while `content` arrives. The header holds still, the preview grows up to its collapsed height, then follows the end of the document. **Show more** appears once the content passes the preview, over its end, so nothing below it moves.

### Agent

An agent connected with `createAgent` finds the document by its title and reads `open`. `copy()` is always offered, `download(formatId)` while `onDownload` is set and no download is pending, with the `downloads` listed as its choices, and `expand()` or `collapse()` while the content is taller than the preview. Like any component with a button, it also has UI SDK's generic `press`.
