
## Composition

```text
Message
├── MessageAvatar
├── MessageContent
├── MessageEditor
└── MessageToolbar
    ├── MessageBranch
    │   ├── MessageBranchPrevious
    │   ├── MessageBranchLabel
    │   └── MessageBranchNext
    └── KindToolbar
        ├── MessageCopy
        ├── MessageRegenerate
        │   └── MessageRegenerateContent
        │       └── MessageRegenerateRows
        └── MessageEdit
```

The content holds the message, rendered however you like, for example with Markdown. The editor is a text area that takes the content's place while a user message is edited. `MessageCopy`, `MessageRegenerate` and `MessageEdit` each wrap a `KindToolbarButton` and give it its icon and action. The toolbar they sit in is one Tab stop, and the arrow keys move between its buttons. `MessageBranch` switches between responses, with a label like "2 of 3". While the message has `regenerateOptions`, `MessageRegenerate` turns its button into UI SDK's `MenuTrigger` and adds `MessageRegenerateContent`, UI SDK's `MenuContent`, with `MessageRegenerateRows` inside it.

## Usage

### Role and Status

Set `messageRole` to `user` or `assistant`. A user message sits at the end of the line in a bubble. Set `status` as a response arrives: the toolbar stays hidden while it's `submitted` or `streaming`, and fades in when the message settles.

### Copy

Pass the message's `text`, which copy writes to the clipboard. The icon turns into a check for two seconds, and the message tells screen readers "Copied" politely, or "Copy failed". To copy something else, like Markdown converted to HTML, cancel `onCopy` and write it yourself.

### Regenerate and Edit

Each action shows only when you handle it. Pass `onRegenerate` to show regenerate. Pass `onEdit` to show edit on a user message: pressing it swaps the content for the editor, filled with `text`. Enter or moving focus away saves, and Escape cancels. `onEdit` gets the new text, and isn't called when the text didn't change.

### Regenerate With

Pass `regenerateOptions` to offer ways to regenerate, like a shorter reply or another model. Regenerate then opens a menu: **Try again** first, a separator, then your options, each with an `id`, a `label` and optionally a `description` and an `icon`. Give an option `items` to make it open a submenu of them.

`onRegenerate` keeps its signature, and `details.optionId` says which option was chosen: its `id`, or `undefined` for **Try again** or a plain regenerate. `details.reason` is `regenerate-press` for the button, `item-press` for a menu row and `imperative` for a call through the api. Cancel a menu choice with `details.cancel()` to keep the menu open. Without `regenerateOptions`, Regenerate stays a plain button.

The button keeps its place in the toolbar, so the arrow keys still reach it, and Enter, Space or Down Arrow opens the menu. The menu works like the [Add Menu](./add-menu.mdx)'s: arrow keys move between rows, Right Arrow opens a submenu, and Escape closes it with focus back on the button. It's a popover, or a bottom sheet on small touch screens with `presentation="auto"`, the default; pass `"popover"` or `"sheet"` to choose one.

To change the rows, pass `MessageRegenerateContent` a function of `{ tryAgain, options }` as its children, and render `MessageRegenerateRows` or rows of your own.

### Responses

When a message has more than one response, pass `branchCount` and `branchIndex`, from 0. The previous and next buttons call `onBranchChange` with the index they ask for, and the message shows it once you pass that `branchIndex` back:

```tsx
<Message
  text={replies[index]}
  branchIndex={index}
  branchCount={replies.length}
  onBranchChange={(next) => setIndex(next)}
>
  <MessageContent>{replies[index]}</MessageContent>
  <MessageToolbar>
    <MessageBranch>
      <MessageBranchPrevious />
      <MessageBranchLabel />
      <MessageBranchNext />
    </MessageBranch>
  </MessageToolbar>
</Message>
```

The switcher shows only when `branchCount` is more than 1.

### Agent

An agent connected with `createAgent` reads each message's `status`, `branchIndex` and `branchCount`. It can run these actions, and press the buttons like a person would. Each one is offered only while the message shows it. `regenerate` takes a regenerate option's `id` or label, refuses an unknown one, and is **Try again** without one:
