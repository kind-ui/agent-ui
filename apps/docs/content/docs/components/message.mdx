Use a message for each turn in a conversation, from the person or the assistant. Its toolbar holds the actions you handle, and shows once the message is done streaming.

## Installation

```bash tab="React"
npx shadcn@latest add @kind-ui/message
```

```bash tab="Web Components"
npx shadcn@latest add @kind-ui/message-web
```

## Composition

```text
Message
├── MessageAvatar
├── MessageHeader
│   ├── MessageAuthor
│   ├── MessageTime
│   └── MessageDuration
├── MessageContent
├── MessageEditor
│   └── MessageEditActions
│       ├── MessageEditCancel
│       └── MessageEditSave
├── MessageOutcome
│   ├── MessageOutcomeIcon
│   ├── MessageOutcomeText
│   ├── MessageRetry
│   └── MessageContinue
└── MessageToolbar
    ├── MessageBranch
    │   ├── MessageBranchPrevious
    │   ├── MessageBranchLabel
    │   └── MessageBranchNext
    └── KindToolbar
        ├── MessageCopy
        ├── MessageRegenerate
        │   └── MessageRegenerateContent
        │       └── MessageRegenerateRows
        └── MessageEdit
```

The avatar and header show who wrote the message and when. The content holds the message, rendered however you like, for example with Markdown. The outcome sits after the content and says a response stopped or failed. The editor is a text area that takes the bubble's place while a user message is edited, with **Cancel** and **Save** after it in place of the toolbar. `MessageCopy`, `MessageRegenerate` and `MessageEdit` each wrap a `KindToolbarButton` and give it its icon and action. The toolbar they sit in is one Tab stop, and the arrow keys move between its buttons. `MessageBranch` switches between responses, with a label like "2 of 3". While the message has `regenerateOptions`, `MessageRegenerate` turns its button into UI SDK's `MenuTrigger` and adds `MessageRegenerateContent`, UI SDK's `MenuContent`, with `MessageRegenerateRows` inside it.

## Usage

### Role and Status

Set `messageRole` to `user` or `assistant`. A user message sits at the end of the line in a bubble. Set `status` as a response arrives: the toolbar stays hidden while it's `submitted` or `streaming`, and fades in when the message settles. On a device with a pointer, a message that isn't the last one shows its actions only on hover or while focus is inside it; the last message, and every message on a touch screen, always shows them. A branch switcher always shows, since it says something. The last message is the last `ConversationRow`, or the last of sibling messages.

### Author and Time

Pass `author`, with an `id`, a `name` and optionally an `avatarUrl`, to fill `MessageAvatar` with their image, or their initials until it loads, and `MessageAuthor` with their name. Pass `createdAt`, an ISO 8601 date-time, for `MessageTime`, and `durationSeconds` for `MessageDuration`, which reads like "4 sec" or "1 min 12 sec". `MessageHeader` holds all three, and shows while any of them has something to show.

The time reads "9:41 AM" for a message from today, and "Nov 17, 9:41 AM" for one from another day. Server markup has no clock, so it shows the date and time, and the browser reads today from its clock once the page loads. Pass `now` to set today yourself. Times read in `timeZone`, UTC by default, and dates and durations in `locale`, English by default.

Set `continued` on a message that follows its author's previous one, to leave out its avatar and name. The avatar keeps its space, so the messages stay lined up. `isContinuation(previous, next)` from `@kind-ui/agent-ui/core` says whether two messages have the same author `id` and were written within five minutes of each other; pass `{ withinMinutes }` to change that.

### Stopped and Failed Answers

When a response stops or fails, `MessageOutcome` says so after the content, so the streamed text above it never moves. Set `status` to `aborted` to show "Stopped", or to `error` to show the `error` option's words, "Something went wrong" by default. Pass `onContinue` to offer **Continue** on a stopped response, and `onRetry` to offer **Retry** on a failed one.

<Example caption="Press Continue to finish the stopped answer, or Retry to try the failed one again. Each button stays unavailable while its request is pending.">

  <include cwd lang="tsx">./examples/message/outcomes.tsx</include>

Both callbacks get `details.reason`: `retry-press` or `continue-press` for the button, `imperative` for a call through the api. Return a promise to keep the button unavailable until it settles. If it rejects, the button is available again. A new `status` ends the pending request too.

The message tells screen readers "Response stopped" or "Response failed" politely, once, and only when it saw that response streaming, so a page of earlier messages stays quiet. With the [AI SDK adapter](../adapters/ai-sdk.mdx), `fromUIMessages(messages, { status, error })` puts the chat's error on the last message, so pass that message's `error.message` as `error`.

### Copy

Pass the message's `text`, which copy writes to the clipboard. The icon turns into a check for two seconds, and the message tells screen readers "Copied" politely, or "Copy failed". To copy something else, like Markdown converted to HTML, cancel `onCopy` and write it yourself.

### Regenerate and Edit

Each action shows only when you handle it. Pass `onRegenerate` to show regenerate. Pass `onEdit` to show edit on a user message: pressing it swaps the bubble for the editor, filled with `text`, in the same place. **Save**, Enter or moving focus away saves, and **Cancel** or Escape cancels. Tab moves from the editor to **Cancel** and **Save**. `onEdit` gets the new text, and isn't called when the text didn't change.

### Regenerate With

Pass `regenerateOptions` to offer ways to regenerate, like a shorter reply or another model. Regenerate then opens a menu: **Try again** first, a separator, then your options, each with an `id`, a `label` and optionally a `description` and an `icon`. Give an option `items` to make it open a submenu of them.

  <include cwd lang="tsx">./examples/message/regenerate-options.tsx</include>

`onRegenerate` keeps its signature, and `details.optionId` says which option was chosen: its `id`, or `undefined` for **Try again** or a plain regenerate. `details.reason` is `regenerate-press` for the button, `item-press` for a menu row and `imperative` for a call through the api. Cancel a menu choice with `details.cancel()` to keep the menu open. Without `regenerateOptions`, Regenerate stays a plain button.

The button keeps its place in the toolbar, so the arrow keys still reach it, and Enter, Space or Down Arrow opens the menu. The menu works like the [Add Menu](./add-menu.mdx)'s: arrow keys move between rows, Right Arrow opens a submenu, and Escape closes it with focus back on the button. It's a popover, or a bottom sheet on small touch screens with `presentation="auto"`, the default; pass `"popover"` or `"sheet"` to choose one.

To change the rows, pass `MessageRegenerate` a `menuContent`: a `MessageRegenerateContent` whose children are a function of `{ tryAgain, options }`, rendering `MessageRegenerateRows` or rows of your own.

### Responses

When a message has more than one response, pass `branchCount` and `branchIndex`, from 0. The previous and next buttons call `onBranchChange` with the index they ask for, and the message shows it once you pass that `branchIndex` back:

```tsx
<Message
  text={replies[index]}
  branchIndex={index}
  branchCount={replies.length}
  onBranchChange={(next) => setIndex(next)}
>
  <MessageContent>{replies[index]}</MessageContent>
  <MessageToolbar>
    <MessageBranch>
      <MessageBranchPrevious />
      <MessageBranchLabel />
      <MessageBranchNext />
    </MessageBranch>
  </MessageToolbar>
</Message>
```

The switcher shows only when `branchCount` is more than 1.

### Agent

An agent connected with `createAgent` reads each message's `status`, `branchIndex` and `branchCount`. It can run these actions, and press the buttons like a person would. Each one is offered only while the message shows it. `regenerate` takes a regenerate option's `id` or label, refuses an unknown one, and is **Try again** without one. `retry` and `continue` are offered on a failed or stopped response while you handle them and nothing is pending:
