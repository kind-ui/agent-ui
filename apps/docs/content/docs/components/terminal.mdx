## Composition

```text
Terminal
├── TerminalTrigger
│   ├── TerminalIcon
│   ├── TerminalTitle
│   ├── TerminalExit
│   └── TerminalMeta
├── TerminalApproval
│   └── Confirmation
└── TerminalContent
    └── div[data-terminal-screen]
        ├── div[data-terminal-header]
        │   ├── TerminalCommand
        │   └── TerminalCopy
        ├── TerminalViewport
        │   └── TerminalOutput
        │       └── TerminalLine
        └── TerminalJump
```

`TerminalTrigger` opens and closes the run, with its status mark in `TerminalIcon`, the command in `TerminalTitle`, "exit N" in `TerminalExit` and the duration in `TerminalMeta`. `TerminalContent` holds the screen, a `div` with `data-terminal-screen` and `data-kind-code` that the stylesheet draws as a code surface and places **Jump to latest** in. In it, `TerminalCommand` shows the command after a `$` prompt, only when a `label` takes its place as the title, `TerminalCopy` copies the output from the screen's corner, and `TerminalViewport` scrolls `TerminalOutput`, which renders a `TerminalLine` for each line in view. `TerminalJump` shows while you've scrolled away from the end. `TerminalApproval` sits between the header and the screen while the command has an `approval`, with a [Confirmation](./confirmation.mdx) in it.

## Usage

### Output

Pass `command` and `output`, the whole output so far with its ANSI escapes, and pass the whole output again on each update. When it continues the last one, only the new text is parsed, so a long run streams as fast as a short one. Text styles (the 16 colors, 256-color and truecolor, bold, dim, italic, underline, strikethrough and inverse) show as styled text, never HTML. Every other escape, like a cursor move or a window title, is dropped. A lone `\r` starts its line again, so a progress bar shows its last state.

The 16 colors come from `--kind-ansi-*` tokens, like `--kind-ansi-red` and `--kind-ansi-bright-blue`, tuned to read on the screen in light and dark. Set them in your theme to use your own palette.

### Status and Exit Code

Without `status`, a run is `running` until you pass `exitCode`, then `complete` for 0 and `error` for anything else. A running step opens and shows a cursor after its last line; once it completes, it closes to its header, and a failed run stays open. A person who opens or closes it keeps it that way. Pass `durationSeconds` to show how long it took. The outcome is announced once: "npm test complete", or "npm test failed, exit code 1". Lines aren't announced.

```tsx
<Terminal command="npm run build" output={output} exitCode={done ? code : undefined} />
```

### Approve a Command

Pass `approval` to ask before the command runs. A Confirmation asks "Run npm test?" under the header, with **Approve** for `onApprove`, **Always allow** for `onAlwaysAllow` and **Deny** for `onDeny`, and the run's status is `awaiting-input`. Each is called with the approval's `approvalId` and `generation`; Always allow adds `always: true`, so you can add the command to your allow list, which stays yours. `approvalReason` adds a box for the reason Deny sends.

The screen stays out of the way until the command prints something, and the outcome stays where the choices were, so the output shows after it and nothing above moves. A denied command keeps its header and shows "Denied" with the reason; its status is `cancelled`. The confirmation announces the decision.

### Following the End

While new output arrives, the view stays at the end. Scroll up and it stays where you are while lines keep arriving, and **Jump to latest** appears; press it to go back to the end and follow again. Only the lines in view are rendered, so thousands of lines scroll as smoothly as ten. The screen grows with the output up to `--kind-terminal-max-height` (20rem), then scrolls.

### Copying

**Copy output** shows once there's output, in the screen's corner while you point at the screen or focus inside it, copies it without its escapes and shows a check for 2 seconds. Pass `onCopy` to hear about it; cancel its `details` to copy something else yourself.

### Keyboard and Motion

Tab reaches the header, **Copy output** and the output, which scrolls with the arrow keys, Page Up and Page Down. The screen opens and closes with the step's height animation; under `prefers-reduced-motion`, or with `motion="reduced"`, it fades over 120 ms and the cursor stops blinking, and with `motion="none"` nothing moves.

### Agent

An agent connected with `createAgent` finds the run by its title, the command unless you pass `label`, and reads `open`, `status` and `following`. It can `expand` and `collapse` the run and, once there's output, `copy` it, which calls `onCopy` too. Its approval is a Confirmation of its own, named "Run npm test?", whose decisions always wait for a person to confirm.
