Use a terminal when the agent runs a shell command, so readers can follow its output while it runs and check its exit code once it's done. It's a step: a header with the command, its exit code and how long it took, over a screen with the output.

## Composition

```text
Terminal
├── TerminalTrigger
│   ├── TerminalIcon
│   ├── TerminalTitle
│   ├── TerminalExit
│   └── TerminalMeta
├── TerminalApproval
└── TerminalContent
    └── div[data-terminal-screen]
        ├── div[data-terminal-header]
        │   ├── TerminalCommand
        │   └── TerminalCopy
        ├── TerminalViewport
        │   └── TerminalOutput
        │       └── TerminalLine
        └── TerminalJump
```

`TerminalTrigger` opens and closes the run, with its status mark in `TerminalIcon`, the command in `TerminalTitle`, "Exit N" for a failed run in `TerminalExit` and the duration in `TerminalMeta`. `TerminalApproval` holds a Confirmation while the command has an `approval`. `TerminalContent` holds the screen, a `div` with `data-terminal-screen` and `data-kind-code` that the stylesheet draws as a code surface and places **Jump to latest** in. In it, `TerminalCommand` shows the command after a `$` prompt, only when a `label` takes its place as the title, `TerminalCopy` copies the output from the screen's corner, and `TerminalViewport` scrolls `TerminalOutput`, which renders a `TerminalLine` for each line in view. `TerminalJump` shows while you've scrolled away from the end.

## Usage

### Output

Pass `command` and `output`, the whole output so far with its ANSI escapes, and pass the whole output again on each update. When it continues the last one, only the new text is parsed, so a long run streams as fast as a short one. Text styles (the 16 colors, 256-color and truecolor, bold, dim, italic, underline, strikethrough and inverse) show as styled text, never HTML. Every other escape, like a cursor move or a window title, is dropped. A lone `\r` starts its line again, so a progress bar shows its last state.

The 16 colors come from `--kind-ansi-*` tokens, like `--kind-ansi-red` and `--kind-ansi-bright-blue`, tuned to read on the screen in light and dark. Set them in your theme to use your own palette.

### Status and Exit Code

Without `status`, a run is `running` until you pass `exitCode`, then `complete` for 0 and `error` for anything else. A running step opens and shows a cursor after its last line; once it completes, it closes to its header, and a failed run stays open. A person who opens or closes it keeps it that way. Pass `durationSeconds` to show how long it took. The header says the result once: "6 sec", or "Exit 1 · 6 sec". The outcome is announced once: "npm test complete", or "npm test failed, exit code 1". Lines aren't announced.

```tsx
<Terminal command="npm run build" output={output} exitCode={done ? code : undefined} />
```

### Approval

Pass an `approval` to ask before the command runs. While it waits, the title asks "Run `npm test`?" with the whole command, the header reads "Waiting for approval", and **Deny**, **Always allow** and **Run** sit under it. Only the choices whose callbacks you pass show; Always allow takes `alwaysTarget`, `alwaysScope` and `alwaysDetail`, as [Confirmation](./confirmation)'s does. The run can't be closed while it waits.

Record the decision on `approval`, as with a Confirmation. The choices turn into what was decided, in place, and the output grows below it. Once the command ends, its result goes in the header and the outcome keeps the decision, so "Always allowed `npm test` in this project" stays in view. A denied command shows a slash in its header mark, an expired one a clock, and neither shows output. With `risk="danger"` and a `riskText`, the risk shows in words, **Run** turns red and Always allow isn't offered.

### Following the End

While new output arrives, the view stays at the end. Scroll up and it stays where you are while lines keep arriving, and **Jump to latest** appears; press it to go back to the end and follow again. Only the lines in view are rendered, so thousands of lines scroll as smoothly as ten. The screen grows with the output up to `--kind-terminal-max-height` (20rem), then scrolls.

### Copying

**Copy output** shows once there's output, in the screen's corner while you point at the screen or focus inside it, copies it without its escapes and shows a check for 2 seconds. Pass `onCopy` to hear about it; cancel its `details` to copy something else yourself.

### Keyboard and Motion

Tab reaches the header, **Copy output** and the output, which scrolls with the arrow keys, Page Up and Page Down. The screen opens and closes with the step's height animation; under `prefers-reduced-motion`, or with `motion="reduced"`, it fades over 120 ms and the cursor stops blinking, and with `motion="none"` nothing moves.

### Agent

An agent connected with `createAgent` finds the run by its title, the command unless you pass `label`, and reads `open`, `status` and `following`. It can `expand` and `collapse` the run and, once there's output, `copy` it, which calls `onCopy` too. A waiting approval is its own Confirmation, whose `approve`, `deny` and `alwaysAllow` always need a person to confirm.
