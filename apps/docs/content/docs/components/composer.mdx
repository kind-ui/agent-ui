Use a composer where someone writes a prompt. It holds the text, the mentions and commands typed into it, and the attached files, and sends them together as one draft.

## Composition

```text
Composer
├── ComposerAttachments
├── ComposerInput
│   └── ComposerTriggerMenu
├── ComposerAttach
├── ComposerRestored
│   └── ComposerDiscard
├── ComposerSubmit
├── ComposerStop
└── ComposerSendMenu
    ├── ComposerSteer
    └── ComposerSendMenuTrigger
```

The composer renders a form, and everything inside it takes dropped files. `ComposerAttachments` shows the attached files as [Attachments](./attachments.mdx), and stays empty until there are some. `ComposerInput` is the prompt, and `ComposerTriggerMenu` inside it shows the suggestions. `ComposerAttach` opens the file picker. `ComposerRestored` says when a saved draft came back, with `ComposerDiscard` inside it, and shows nothing otherwise. `ComposerSubmit` and `ComposerStop` are Send and Stop, which take turns in the same place. `ComposerSendMenu` is Send while a turn runs: `ComposerSteer` and the chevron, `ComposerSendMenuTrigger`, that opens the other ways to send. Name the composer and its input with `aria-label`.

## Usage

### Sending

Enter sends the draft to `onSubmit`, and Shift+Enter starts a new line. Pass `submitOn="mod-enter"` to send with Ctrl+Enter or Cmd+Enter instead, so Enter starts a new line. A draft with only whitespace doesn't send.

The draft has `text`, `tokens` and `attachments`. In `text`, each mention or command reads `[@label](kind:value)`, and `tokens` lists them in order:

```tsx
<Composer
  aria-label="Message"
  onSubmit={(draft) => chat.send(draft.text, draft.attachments)}
>
```

Return a promise from `onSubmit` to keep the composer pending: Send is locked, and screen readers hear "Sending". When the promise resolves, the draft clears, unless someone kept typing in the meantime. When it rejects, the draft stays and screen readers hear "Message not sent".

To own the draft, pass `value` and `onValueChange`. Cancel the change's `details` to refuse an edit, and the prompt goes back to the draft.

### Stop

Pass `onStop` to show Stop in Send's place while a submission is pending, so someone can end the agent's reply. Settle the `onSubmit` promise once it stops, and Send comes back. When the button that had focus leaves, focus moves to the one that took its place.

### While a Turn Runs

Pass `running` while the agent works, and Stop shows, named "Stop generating". Enter never starts a new turn then. Pass `onSteer` too, and once there's text, Send shows beside Stop, which turns quiet. Send reads **Steer**: it delivers the draft at the agent's next step. Its chevron opens **Queue for later**, which sends after the turn, and **Stop and send**, which ends the turn and sends the draft as a new one.

`onSteer` gets the draft and `details.mode`: `steer`, `queue` or `stop-and-send`. Add a queued draft to your [Queue](./queue.mdx), and for `stop-and-send`, stop the turn and send the draft as a new one. A promise you return locks sending, as `onSubmit`'s does: resolving clears what was sent and keeps anything typed since. Screen readers hear "Steer sent", "Queued" or "Stopped and sent". Stopping never sends a queued message; those wait for the person.

Enter sends in `steerMode`, Alt+Enter in the other mode, and Shift+Ctrl+Enter or Shift+Cmd+Enter stops and sends. To make Send queue instead, pass `steerMode="queue"`:

```tsx
<Composer aria-label="Message" running={running} onStop={stop} onSteer={send} steerMode="queue">
```

Pass `stopAndSend={false}` to leave Stop and send out of the menu. It's on by default when `onStop` and `onSteer` are both set.

A Queue inside the composer docks to its top edge, with **Send now**, **Edit** and **Remove** on each row. Edit and Alt+Up give the text back to the prompt, on its own line, with the reason `queue-edit`.

### Mentions and Commands

Pass `mentions` to suggest them after `@`, and `commands` to suggest them after `/` at the start of a line. Each item has a `value`, a `label` and an optional `description`. Choosing one inserts it into the prompt as a token, and Escape closes the suggestions.

### Files

Files attach when someone presses `ComposerAttach`, drops them on the composer, or pastes them while it has focus. Pass `accept` and `maxSize` to limit them. A file they rule out still attaches, with its error on the chip, so the person sees why; it has an `error` in the draft, and a draft with only those files doesn't send. Each chip has a remove button, and Delete or Backspace removes the focused one.

### History

Pass earlier prompts as `history`, oldest first. ArrowUp at the start of the prompt brings back the previous one, and ArrowDown moves forward again, back to what was being typed.

### Draft Restore

Pass `draftKey` and `draftStorage` to keep an unsent draft across reloads. `draftKey` names the conversation, and `draftStorage` is a storage from UI SDK's `createLocalStorage` or `createSessionStorage`. One storage holds the drafts of every key, so create it once, outside render, and share it across conversations:

```tsx
import { createLocalStorage } from "@ui-sdk/core";

const drafts = createLocalStorage("drafts");

<Composer
  aria-label="Message"
  draftKey={conversation.id}
  draftStorage={drafts}
  onSubmit={send}
>
```

The text and tokens are saved as they change. Attachments aren't, since files can't be saved. When the composer mounts with an empty draft, or `draftKey` changes while the prompt is empty, the saved draft comes back. It never replaces text someone typed: text kept through a `draftKey` change stays saved under the conversation it was written in.

When a draft comes back, screen readers hear "Draft restored", and `ComposerRestored` shows **Draft restored** with a **Discard** button between Attach and Send, so the prompt doesn't move. The next edit hides it. **Discard** empties the draft, removes it from storage and moves focus to the prompt.

A submission that resolves removes the saved draft, unless someone kept typing in the meantime; then the newer text stays saved. A controlled `value` is never saved or restored, since the host owns it. If storage fails or is full, the composer ignores it and typing keeps working.

### Controls and Narrow Screens

Put the controls a prompt needs in the composer's actions row: wrap them in one element placed in its `attach` area, as `style={{ gridArea: "attach" }}`, and let it wrap. Keep them few: settings a prompt rarely changes fit in [Model Control](./model-control.mdx)'s menu rather than a trigger of their own. A [Context Bar](./context-bar.mdx) inside the composer sits above the prompt, and a [Dictation](./dictation.mdx) inside it is a mic button just before Send. While it listens, its waveform takes the prompt's place and its Cancel, status and Stop take the last line of the actions row, beside Send, and the composer keeps its size. When it stops, it adds what it heard to the end of the draft, with the reason `dictation`. Call `appendText(text)` on the composer's api to do the same.

### Agent

An agent connected with `createAgent` reads the composer's `value`, and whether it's pending. It can run these actions, `stop` only while Stop shows, `steer`, `queue` and `stopAndSend` only while Send shows beside it, and `discardDraft` only while **Draft restored** shows. While `agentConfirm` is on, every one of them waits for a person to confirm, unless the host's `allow` lets it through:
