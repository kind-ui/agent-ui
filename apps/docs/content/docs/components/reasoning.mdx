## Composition

```text
Reasoning
├── ReasoningTrigger
│   ├── ReasoningIcon
│   └── ReasoningTitle
└── ReasoningContent
```

`Reasoning` renders these parts when you pass no children; any children you pass replace them. The trigger is a native button that shows or hides the content. `ReasoningTitle` shows the title, or its own children, and `ReasoningContent` renders `text` as [Markdown](./markdown.mdx), or its own children. When you compose the parts yourself, keep `ReasoningTitle` or pass `label`: the title names the reasoning and is what it announces.

## Usage

### Streaming Thoughts

Pass the thoughts so far as `text`, and set `status` as the model works. While the status is `running`, the title shimmers, the content stays open and `text` renders as streaming Markdown: each chunk parses only the blocks it changed, and the trigger above never moves.

```tsx
<Reasoning status={isThinking ? "running" : "complete"} durationSeconds={seconds} text={reasoningText} />
```

### Summary

When the status turns `complete`, the title becomes "Thought for N s", from `durationSeconds` rounded to the nearest second and never less than 1, or "Thought" without one. The content closes on its own, unless someone opened or closed it while the model thought. Pass `label` to replace the title with your own words.

A reasoning that goes straight from `pending` to `complete`, like a cached answer, stays closed.

### Announcements

When the model finishes, screen readers hear the title, like "Thought for 4 s", once. A failure says "Thinking failed" and a cancelled run "Thinking stopped". Streamed text is quiet. On Web Components, set `duration-seconds` before `status`, so the announced summary has the duration.

### Motion

The content grows open and shut. Under `prefers-reduced-motion`, or with `motion="reduced"`, it fades over 120 ms instead and the title holds still, and with `motion="none"` it changes at once.
