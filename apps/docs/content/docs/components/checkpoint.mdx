Use a checkpoint where the agent saved its work, like before it edits a file, so a person can undo everything after it. It's a quiet line in the conversation with **Restore checkpoint** at its end, and nothing is restored until the person agrees in the dialog.

## Composition

```text
Checkpoint
├── CheckpointLabel
├── CheckpointDescription
├── CheckpointLine
├── CheckpointRestore
│   └── CheckpointDialog
│       ├── CheckpointError
│       ├── CheckpointCancel
│       └── CheckpointConfirm
└── CheckpointRestored
```

`Checkpoint` renders these parts when you pass no children: a group named by its `label` and described by its `description`, then a line to the end of the row. `CheckpointRestore` holds UI SDK's Alert Dialog: its trigger is an icon button named by a tooltip, and `CheckpointDialog` is its backdrop and content, with the title, the description and the answers. `CheckpointCancel` and `CheckpointConfirm` are native buttons. `CheckpointRestored` takes Restore's place once the checkpoint is restored.

## Usage

### Restoring

Pass `onRestore` to show **Restore checkpoint**. Pressing it opens the dialog, which asks "Restore this checkpoint?" and says "Changes after it will be discarded."; set `confirmTitle` and `confirmDescription` to say more about your checkpoint.

```tsx
<Checkpoint
  label="Checkpoint 3"
  description="Before editing auth.ts"
  onRestore={() => restoreFiles("checkpoint-3")}
/>
```

Only the dialog's **Restore** calls `onRestore`, with `details.source` saying how it was pressed. Return a promise to keep the dialog open until it settles: **Restore** shows a running mark beside its label and the dialog is marked busy, both answers are disabled meanwhile, a second press calls nothing, and Escape waits. When it resolves, the dialog closes and focus returns to **Restore checkpoint**. A rejection keeps the dialog open with "Couldn't restore. Try again." beside the answers, and screen readers hear "Checkpoint not restored".

### Restored

Once the host has restored the checkpoint, pass `restored`. "Restored" takes the button's place at the same height, so nothing above or below it moves, and screen readers hear "Checkpoint restored". If the button had focus, focus moves to "Restored". Setting `restored` while the dialog is open closes it.

### Keyboard

**Restore checkpoint** is one Tab stop; Enter or Space opens the dialog with focus on **Cancel**, the answer that changes nothing. Tab stays inside the dialog, and Escape closes it and returns focus to the button. A press outside never closes it.

### The Dialog's State

Pass `open` and `onOpenChange` to control the dialog, or `defaultOpen` to start with it open. `onOpenChange` gets UI SDK's reason, like `trigger-press`, `escape-key`, `close-press` or `action` after a restore.

### Motion

The dialog rises and fades in, its backdrop and the tooltip fade, and "Restored" fades in. Under `prefers-reduced-motion`, or with `motion="reduced"`, these only fade, over 120 ms, and with `motion="none"` they change at once.

### Agent

An agent connected with `createAgent` finds the checkpoint by its label and reads whether its dialog is open. Its `restore` opens the dialog, the same as a press, and is offered while **Restore checkpoint** shows and the dialog is closed. It never calls `onRestore`: only the dialog's **Restore** does, and an agent pressing that always needs a person to confirm, unless the host's `allow` lets it through. While `agentConfirm` is on, `restore` and every other action on the checkpoint need a person too.
