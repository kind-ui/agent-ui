## Composition

```text
AgentCard
├── AgentCardAvatar
├── AgentCardName
├── AgentCardStatus
├── AgentCardModel
├── AgentCardAction
├── AgentCardDescription
└── AgentCardCapabilities
    └── AgentCardCapability
```

`AgentCard` renders every part. Each part shows what `agent` holds unless you pass children, and leaves itself out when there's nothing to show: no model, no description, no capabilities, no `status`, or no `onAction`. To arrange the parts yourself, use `AgentCardRoot`.

## Usage

### Agent

Pass `agent`: its `id` and `name`, and any of `avatarUrl`, `model`, `description` and `capabilities`. The avatar shows the image, or the name's initials until it loads or without one; it's hidden from screen readers, since the name beside it says who the agent is. Capabilities read as a list of badges.

The name is a heading, level 3 unless you pass `level` (1 to 6). Pass `href` to make it a link to the agent; only `http`, `https` and `mailto` URLs link.

### Status

Pass `status` to show what the agent is doing, as a status mark and words: "Waiting", "Working", "Needs input", "Done", "Failed" or "Stopped". Without one the card shows no status.

### Action

Pass `onAction` to show one button, "Open" unless you pass `actionLabel` ("Start", "Chat"). It's called with the agent's `id` and `{ reason, source }`. Its accessible name adds the agent's name ("Open Planner"), so cards side by side don't all read "Open".

The card has no popup of its own. To show it when someone hovers an agent's name, put it in a hover card of your own.

### Agent

An agent connected with `createAgent` finds the card by the agent's name. `run()` does what the action button does, offered while `onAction` is set. It doesn't ask a person first.
