Use a status badge beside a run, a job or a tool call to show whether it's waiting, running, needs input or is done. Its mark and its text both say the status, so it never depends on color alone.

## Installation

```bash tab="React"
npx shadcn@latest add @kind-ui/status
```

```bash tab="Web Components"
npx shadcn@latest add @kind-ui/status-web
```

## Composition

```text
Status
├── StatusIcon
└── StatusLabel
```

`Status` renders both parts when you pass no children; any children you pass replace them. `StatusIcon` draws the mark and is hidden from screen readers, and `StatusLabel` shows the label, or its own children.

## Usage

### Status and Label

Set `status` as the work moves along: `pending`, `running`, `awaiting-input`, `complete`, `error` or `cancelled`. The label follows it: "Pending", "Running", "Needs input", "Complete", "Failed" or "Cancelled". Pass `label` for your own words, like "Deployed".

A new label can change the badge's width, so put it at the end of a row, where nothing comes after it. Its height stays the same for every status.

### Announcements

When the status changes to `awaiting-input`, `complete`, `error` or `cancelled`, the badge tells screen readers its label, politely. Other changes, and label changes while the status stays the same, are quiet. The badge takes no focus and has no keys.

### Motion

The mark morphs from one status to the next. Under `prefers-reduced-motion`, or with `motion="reduced"`, it fades over 120 ms instead, and with `motion="none"` it changes at once.

### Agent

An agent connected with `createAgent` sees each badge as a `kind-status` and reads its `status`. It has no actions.
