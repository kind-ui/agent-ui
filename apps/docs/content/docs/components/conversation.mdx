## Composition

```text
Conversation
├── ConversationViewport
│   └── ConversationContent
│       ├── ConversationRow
│       ├── ConversationSkeleton
│       ├── ConversationLoading
│       ├── ConversationError
│       │   ├── ConversationErrorIcon
│       │   ├── ConversationErrorText
│       │   └── ConversationRetry
│       └── ConversationEmpty
│           ├── ConversationEmptyTitle
│           └── ConversationEmptyDescription
├── ConversationJump
└── ConversationMarks
    └── ConversationMark
```

The viewport is the part that scrolls, and the content holds a `ConversationRow` for each message, with its `value` and `index`. The other parts of the content take the rows' place when there are none to show: `ConversationSkeleton` and `ConversationLoading` while the conversation loads, `ConversationError` when it couldn't load, and `ConversationEmpty` once it's loaded with no messages. `ConversationJump` renders a button that shows while the reader is away from the end, and `ConversationMarks` a track beside the scrollbar with a `ConversationMark` for each marked message.

## Usage

### Following New Messages

Pass the number of messages as `messageCount`. While the reader is at the end, new messages and messages that grow as they stream stay in view. Once they scroll up, the conversation stops following and counts the messages that arrive. Scrolling back to the end follows again.

Each new row fades in once, when it mounts. A row that renders again, or a message that keeps streaming, doesn't replay it.

### Jump to Latest

While the reader is away from the end, `ConversationJump` shows **Jump to latest**, or the count, like **3 new messages**, once messages arrive. Pressing it scrolls to the end and follows again. The button writes its own text, so render it without children.

The conversation tells screen readers the new-message count politely as it grows. The viewport is a single Tab stop, so the keyboard can scroll the log even when nothing in it is focusable.

### Loading and Errors

Pass `status` to say whether the messages are there yet. While it's `"loading"`, `ConversationSkeleton` shows three placeholder rows shaped like what loads (a question's bubble, an answer's lines of text, then another bubble), hidden from screen readers, and `ConversationLoading` tells them "Loading conversation" instead. Put both in the content and render your rows only once the messages arrive.

While `status` is `"error"`, `ConversationError` shows an error mark and the `error` text, "Couldn't load this conversation" by default, and **Retry** when you pass `onRetry`. Return a promise from `onRetry` to keep **Retry** pending until it settles, so a second press doesn't load again. An error the conversation mounts with is a status, and one that appears later is an alert, so screen readers hear it right away. Pass children to `ConversationError` to arrange `ConversationErrorIcon`, `ConversationErrorText` and `ConversationRetry` yourself.

Set `messageCount` before `status` turns `"ready"`, so the loaded messages appear at once instead of playing the new-message entrance.

### Empty State

`ConversationEmpty` shows while `status` is `"ready"` and `messageCount` is 0, and centers what you put in it. Give it a `ConversationEmptyTitle` and a `ConversationEmptyDescription`, and anything that helps the person start, like a [Suggestion](./suggestion.mdx):

### Scrolling From Outside

Pass a `controller` from `createConversationController()` to scroll and read the conversation from your own code. Call its `scrollToEnd()` to jump to the newest message, for example after the person sends one. Before you add older messages above, call `prepend()`, so the reader keeps their place and the older messages aren't counted as new:

```tsx
import { createConversationController } from "@kind-ui/agent-ui/core";

const controller = createConversationController();

async function loadOlder() {
  const older = await fetchOlderMessages();
  controller.prepend();
  setMessages((messages) => [...older, ...messages]);
}
```

### Marks Beside the Scrollbar

Pass `marks` the indexes of messages to point out, like the ones a search matched, and render `ConversationMarks` inside the Conversation. It draws a mark for each beside the scrollbar, at the message's place in the conversation, and marks closer than 4px merge into one, so a thousand matches stay readable. The track is decorative and hidden from screen readers. [Conversation Search](./conversation-search.mdx) hands you its matches through `onMarksChange`.

```tsx
<Conversation messageCount={messages.length} marks={[2, 7]}>
  <ConversationViewport>{/* rows */}</ConversationViewport>
  <ConversationMarks />
</Conversation>
```

### Long Conversations

Pass `virtualize` to render only the rows in view. Render rows from the content's `rows`, keyed by index, and pass `rowKey` so each measured height stays with its message:

```tsx
<Conversation messageCount={messages.length} virtualize rowKey={(index) => messages[index].id}>
  <ConversationViewport>
    <ConversationContent>
      {({ rows }) =>
        rows.map((row) => (
          <ConversationRow key={row.index} value={row.key} index={row.index}>
            {messages[row.index].text}
          </ConversationRow>
        ))
      }
    </ConversationContent>
  </ConversationViewport>
  <ConversationJump />
</Conversation>
```

`virtualize` is read once, when the conversation mounts. Until a row is measured, it's `estimateRowHeight` tall.
