## Composition

```text
Tool
├── ToolTrigger
│   ├── ToolIcon
│   ├── ToolTitle
│   └── ToolMeta
├── ToolContent
│   ├── ToolInput
│   │   └── ToolInputCopy
│   ├── ToolOutput
│   │   └── ToolOutputCopy
│   ├── ToolRetry
│   └── ToolError
│       └── ToolRetryButton
└── ToolApproval
```

`Tool` renders these parts when you pass no children; any children you pass replace them. The trigger is a native button that shows or hides the content. `ToolTitle` shows the tool's name and `ToolMeta` how long the call took, like "2 s", once you pass `durationSeconds`; `ToolInput` and `ToolOutput` the values as a [Code Block](./code-block.mdx) or [Markdown](./markdown.mdx), `ToolRetry` a retry in progress, and `ToolError` the error with `ToolRetryButton`. `ToolApproval` renders a [Confirmation](./confirmation.mdx) while the call has an approval, after the content, so it shows while the tool is closed. Each takes its own children instead.

## Usage

### Tool Calls

Pass the call as `call` and update it as the host does. With the [AI SDK](../adapters/ai-sdk.mdx), `fromUIMessagePart` maps each tool part to a step whose `call` and `error` you pass on. Key each tool by its `toolCallId`: updating one call never closes another tool or clears its copied state.

```tsx
<Tool key={step.id} call={step.call} error={step.error} />
```

The status comes from the call. An error outcome is `error`, a denied or cancelled one is `cancelled`, an approval that's waiting is `awaiting-input`, final output is `complete`, and anything else is `running`. Pass `status` to set it yourself.

### Input and Output

The input shows as JSON, an object of up to three plain values on one line, labeled **Partial** while it streams. Output appears once the call has some: text renders as Markdown, and any other value as JSON, so `0`, `false`, `""` and `null` show as themselves. Output that may still change is labeled **Preliminary**. JSON longer than its block scrolls inside it, and nothing above a value moves while it streams.

Each has a copy button, shown once there's a value while the pointer is over its section or focus is in it (always on touch screens), that copies it as shown, checks for 2 seconds and announces "Copied". The buttons and code blocks are named after the tool, like "Copy search_docs input" and "search_docs input", so people and agents can tell two tools apart. Pass `highlight` to color both, as Code Block's does.

### Approvals and Errors

While the call has an approval, the tool shows a [Confirmation](./confirmation.mdx) named after it, like "Run search_docs?". Pass `onApprove` and `onDeny` to offer **Approve** and **Deny**; each is called with the approval's `approvalId` and `generation`, and `approvalReason` adds a box for the reason Deny sends. `toApprovalResponse` comes from the [AI SDK adapter](../adapters/ai-sdk.mdx). Without them, it shows where the approval stands, like "Waiting for approval". Once the decision is recorded, the outcome stays, like "Approved". When a choice goes away with focus, focus moves to the tool's trigger.

```tsx
<Tool
  call={step.call}
  onApprove={() => addToolApprovalResponse(toApprovalResponse(step.call.approval, { approved: true }))}
  onDeny={({ reason }) =>
    addToolApprovalResponse(toApprovalResponse(step.call.approval, { approved: false, reason }))
  }
/>
```

The tool's status stays `awaiting-input` until the decision is recorded, even when it wasn't sent.

When the status is `error`, the content shows `error.message`, or "The tool failed." without one.

Pass `onRetry` to show **Retry** after the error. It's called with the call and `{ reason, source }`; return a promise, and Retry stays locked until the call's status changes, so a second press can't run the call twice. A rejection makes it available again. Each tool locks on its own. When Retry goes away with focus, focus moves to the tool's trigger.

```tsx
<Tool call={step.call} error={step.error} onRetry={(call) => rerunTool(call)} />
```

### Retrying

While the host retries a call, pass the call's `retry`, or `retry` on the tool: its `attempt`, and optionally `maxAttempts`, `retryAt` and `reason`. The status stays what it is, and the content shows a line under the output, like "Retrying, attempt 2 of 5, in 4 sec. Rate limited", that counts down to `retryAt` each second. Screen readers hear "Retrying, attempt 2" once when an attempt starts, never the countdown. Server markup leaves the countdown out until the page hydrates.

```tsx
<Tool call={{ ...step.call, retry: { attempt: 2, maxAttempts: 5, retryAt, reason: "Rate limited" } }} />
```

### A Fallback for Any Tool

Tool shows any input and output as JSON, so it's the fallback for tools that don't have a view of their own. Keep a map of the ones that do, and render a Tool for the rest:

```tsx
const renderers: Record<string, (props: { call: ToolCall }) => ReactNode> = {
  get_weather: WeatherCard,
};

function ToolPart({ call }: { call: ToolCall }) {
  const Renderer = renderers[call.name] ?? Tool;
  return <Renderer call={call} />;
}
```

When one tool fails and the model runs another instead, that's two calls, so it's two Tools.

### Opening and Closing

A tool opens while it runs or waits for approval, closes into its header when it completes, and stays open when it fails. Once someone opens or closes it, it stays as they left it. Screen readers hear the tool's name and its outcome, like "search_docs complete", when it needs input, completes, fails or is cancelled, and "search_docs denied" when its approval is denied. The confirmation announces the decision itself, like "Approved", and "Decision not sent" when it fails.

### Motion

The content grows open and shut. Under `prefers-reduced-motion`, or with `motion="reduced"`, it fades over 120 ms instead and the title holds still, and with `motion="none"` it changes at once.

### Agent

An agent connected with `createAgent` finds a tool by its name and reads its `open` and `status`. It can run these actions, and press the trigger like a person would. `copyInput` and `copyOutput` are listed only while there's a value to copy, and `retry` only while Retry is offered.
