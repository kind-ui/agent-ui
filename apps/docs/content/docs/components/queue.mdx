## Composition

```text
Queue
├── QueueSection
│   ├── QueueSectionTrigger
│   └── QueueSectionContent
│       └── QueueList
│           └── QueueItem
│               ├── QueueItemIcon
│               ├── QueueItemTitle
│               ├── QueueItemDescription
│               ├── QueueItemSend
│               ├── QueueItemEdit
│               └── QueueItemRemove
└── QueueInstructions
```

`Queue` renders a Queued section and a Completed section when you pass no children, then the instructions. Each `QueueSection` takes a `value` of `pending` or `complete`, and hides while it has no items. Its trigger is a native button that shows or hides the section, with the section's title and count. `QueueList` renders an item for each of the section's items when you pass it no children, and each item shows its mark, title, description, and its Send now, Edit and Remove buttons unless you give it children. A completed item's mark is a check; a queued item's is a grip while `onReorder` lets people move it, and empty otherwise, since every queued item is pending. `QueueInstructions` holds the keys that move and remove items: it's hidden from sight, and screen readers read it with each item.

## Usage

### Items

Pass the items as `items`, each with an `id`, a `title`, an optional `description` and a `status` of `pending` or `complete`. Pending items show under **Queued**, which starts open, and complete ones under **Completed**, which starts closed. Pass `defaultOpenSections`, like `["pending", "complete"]`, to start with others open. When the agent finishes an item, set its `status` to `complete` and keep its `id`, and it moves to Completed.

### Reordering

Pass `onReorder` to let people move queued items. It gets the item's `id`, and `details.index`, where the item goes in `items`. Move it there: the queue shows the order you pass back, and keeps showing the move until your next `items` arrive. Completed items stay where they are.

People drag an item with the pointer, or focus it and press Space or Enter to pick it up, the arrow keys to move it, Home and End to send it to either end, and Space or Enter to drop it. Escape puts it back. Screen readers hear each step, like "Dropped Write the changelog entry at position 1 of 3."

If the item being moved leaves `items`, the move is cancelled, `onReorder` isn't called, and focus moves to its neighbor.

### Removing

Pass `onRemove` to let people remove items. It gets the item's `id`, and you take the item out of `items`. Each item shows a remove button on hover, and Delete or Backspace removes the focused item. Focus then moves to the next item, or the previous one at the end.

### Send Now and Edit

Pass `onSend` to show **Send now** on each queued item, and `onEdit` to show **Edit**. Both get the item's `id`; take it out of `items`. Send now sends the message into the running turn, or as the next message when none runs. Pass `sendDisabledReason`, like "Available after you answer the pending request", while it can't, and Send now is disabled and says why.

### In a Composer

Put the queue inside a [Composer](./composer.mdx#while-a-turn-runs) and it docks to the composer's top edge, part of the same box: a header like "2 queued" that folds it, then each queued message on one line. Completed items don't show. Each row is named "Queued message 1 of 2, not sent". Its buttons show on hover and focus, and always on touch screens and in a narrow composer. Once `onEdit` resolves, the item's title goes back into the prompt, after a line break when there's text, with the caret at its end. Alt+Up in the empty prompt edits the last queued message. The queue grows from the composer's edge as its first item arrives, and folds away after its last leaves.

### Keyboard

The items are one Tab stop, and Tab moves on from the focused item to its buttons. The arrow keys move between them, across both sections while Completed is open, and Home and End go to the first and last. Items in a closed section can't take focus.

### Motion

A new item fades in once as it arrives. A removed item stays in place and fades out, hidden from assistive technology and out of reach, then the items after it slide up into its place. While an item moves, the others slide aside. Under `prefers-reduced-motion`, or with `motion="reduced"`, a removed item fades over 120 ms and nothing slides, and with `motion="none"` it leaves at once.

### Agent

An agent connected with `createAgent` finds the queue by its `label` and reads its `items`, and can name an item by its title. It can run `reorder` while `onReorder` is set and two or more items are queued, `remove` while `onRemove` is set, and `send` and `edit` while `onSend` and `onEdit` are set and an item is queued. Each goes through your callbacks, with `details.source` set to `agent`.

<auto-type-table path="../../../../../packages/agent-ui/src/core/queue/queue.ts" name="QueueAgentActions" type='Pick<QueueApi, "reorder" | "remove" | "send" | "edit">' />

None of them waits for a person to confirm. To ask the person first, return their answer from your `allow`, which also answers every action that does need a person:

```ts
import { createAgent } from "@ui-sdk/react/agent";

const agent = createAgent({
  allow: ({ component, action, confirm }) => {
    if (confirm) return window.confirm(confirm);
    if (component === "kind-queue") return window.confirm(`Let the agent ${action} a queued item?`);
    return true;
  },
});
```

<Caption>
  Runs in React, Vue, Svelte, Solid and Web Components. On `<kind-queue>`, `items` and `openSections` are properties only, and `label` and `motion` are attributes. Reordering needs the `can-reorder` attribute and fires `reorder`, removing needs `can-remove` and fires `remove`, and Send now and Edit need `can-send` and `can-edit` and fire `send` and `edit`, each with the item's `id` in `event.detail.value`; `reorder` also has `event.detail.index`. A `kind-queue` inside a `kind-composer` docks to it. The element fills in its sections and items itself.
</Caption>
