## Mark the Tools That Need a Person

Give the route its tools. `list_branches` runs on its own. `delete_branch` has `needsApproval: true`, so its call waits for a decision before `execute` runs.

```ts title="app/api/chat/route.ts"
import { convertToModelMessages, stepCountIs, streamText, tool, type UIMessage } from "ai";
import { z } from "zod";

const tools = {
  list_branches: tool({
    description: "List the git branches",
    inputSchema: z.object({}),
    execute: async () => [
      { name: "main", merged: false },
      { name: "fix-retry", merged: true },
    ],
  }),
  delete_branch: tool({
    description: "Delete a git branch",
    inputSchema: z.object({ branch: z.string() }),
    needsApproval: true,
    execute: async ({ branch }) => ({ deleted: branch }),
  }),
};

export async function POST(request: Request) {
  const { messages }: { messages: UIMessage[] } = await request.json();
  const result = streamText({
    model: "openai/gpt-5",
    messages: await convertToModelMessages(messages, { tools }),
    tools,
    stopWhen: stepCountIs(5),
    abortSignal: request.signal,
  });
  return result.toUIMessageStreamResponse();
}
```

The model must send its reasoning for the chat to show it; some providers turn that on through their own options.

## Render Reasoning and Tools

The example's code renders each part by its `type`:

- **Reasoning:** a `reasoning` part renders as a Reasoning, `running` while the part streams, so it shows the thoughts, then `complete`, when it collapses to "Thought".
- **Tool calls:** a tool call is a `step` part whose `step.kind` is `"tool"`. Pass its `call` and `error` to a Tool, which shows the input and output and closes into its header when the call completes.
- **Approval:** `onApprove` and `onDeny` show **Approve** and **Deny** while the call waits. Each passes `toApprovalResponse(approval, { approved })` to `addToolApprovalResponse`. Once the decision is recorded, the buttons give way to the outcome, like "Approved".
- **Continuing:** `sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithApprovalResponses` sends the chat back once every waiting call has a decision, so an approved call runs and the model answers.

Pass `approvalReason` to let a person say why they deny a call; `onDeny` gets it as `reason`, which `toApprovalResponse` sends along.
